4. [`orchestrator`](mode:orchestrator) updates this plan file, records the current round, and dispatches the next extraction batch.

- if sufficiency is still not achieved after Round 3, the orchestrator must stop the loop and record one of the following decisions in this plan file:

## Layered design logic

The strategy must remain explicit about the three-layer model that drives the redesign.

### Layer A — DDPM current event capture reality

Purpose:
- identify what DDPM and local response actors can realistically collect during the response phase
- define the minimum event anchor that can populate `DISASTER_RECORD`

Typical evidence:
- initial assessment forms
- MIRA-style rapid assessment fields
- DDPM reporting chain and command structure

Design consequence:
- `DISASTER_RECORD` must be framed as the emergency event anchor, not as a disguised PDNA form

### Layer B — PDNA and DaLA post-disaster assessment requirements

Purpose:
- identify what PDNA and DaLA require after the emergency phase for sectoral valuation and baseline comparison
- separate physical damage, economic loss, recovery needs, and reconstruction needs

Typical evidence:
- PDNA workflow materials
- DaLA methodological sources
- agricultural and sectoral assessment templates

Design consequence:
- damage and loss tables must be modeled as post-disaster analytical structures populated by sectoral assessment work, not by emergency response reporting alone

### Layer C — CRDB target architecture

Purpose:
- synthesize Layer A and Layer B into a traceable Thailand-ready MVD that aligns with NESDC adaptation cues and international logic

Typical evidence:
- NESDC comparison material
- interoperability and standards analysis
- analyst synthesis of DDPM constraints versus international assessment requirements

Design consequence:
- the MVD must explicitly bridge current DDPM capability to a future systematic L&D database without pretending those two states are already the same thing
