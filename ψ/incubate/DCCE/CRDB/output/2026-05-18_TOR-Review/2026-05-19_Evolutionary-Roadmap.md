# Evolutionary Roadmap: The CRDB Knowledge Journey (2026-2028)

## 1. The Realignment: Honesty-First Design
Acknowledging that 90% of the target "Guided Synthesis" functionalities do not yet exist and DCCE lacks the immediate source material, the platform must be positioned not as a "completed product" on day one, but as a **Growing National Asset**. 

The "Selling Point" shifts from **"The Answers are Here"** to **"The Engine to Build the Answers is Now Online."**

---

## 2. Three-Phase Implementation Roadmap

### Phase 1: The Explainer & Baseline (Months 1–6) — "The Trust Phase"
*Focus: Stabilizing the existing 10% and setting the rules.*
*   **Deliverables**: 
    *   **Question-First Hub**: A landing page that maps out the "Big Questions" DCCE *intends* to answer, even if the data isn't there yet (placeholders/narrative guides).
    *   **The Endorsed Registry (MVP-3)**: Publishing the first 10-20 "Official" baseline datasets that *are* available (e.g., TMD projections, National Hazard maps).
    *   **Manual Synthesis**: Humans (Consultants/Staff) upload the first set of "Action Cards" based on existing NAP documents.
*   **Goal**: Stop the confusion. One place to find the "Official" version of what we already have.

### Phase 2: The Synthesis Pilot (Months 6–18) — "The Utility Phase"
*Focus: Translating available data into the first Briefing Packs.*
*   **Deliverables**:
    *   **Template Engine**: Creating the first automated layouts for Provincial Briefs.
    *   **Data-to-Prose Pilot**: Using the Phase 1 baselines to generate the first automated risk summaries for high-priority provinces (e.g., Bangkok, Ayutthaya).
    *   **The "Evidence Label" UI**: Rolling out the trust guardrails on the first batch of pilot datasets.
*   **Goal**: Prove value by reducing reporting workload for a few key regions.

### Phase 3: The Automated Data Space (Years 2+) — "The Scale Phase"
*Focus: API-to-API connectivity and the Data Lake.*
*   **Deliverables**:
    *   **Harvester Nodes**: Activating API connections to TMD, GISTDA, and DDPM to replace manual updates.
    *   **Full Synthesis Engine**: Multi-sector briefing packs and dynamic action-costing.
    *   **Analytical Runway**: Opening the Data Lake for advanced modeling.
*   **Goal**: Sustainability. The system runs on autopilot and scales with DCCE's growing capacity.

---

## 3. Impact on the TOR
By framing it as a roadmap, the TOR requirements change from "Deliver Feature X" to **"Establish the Infrastructure and Logic for Phase 1, with a Mandatory Technical Architecture for Phase 2-3."**

1.  **Contractor Duty**: They are not just "building a site"; they are building the **Logical Schema (CDM)** that can hold the data once it arrives.
2.  **Personnel**: The "Knowledge Broker" is now even more critical—their job in Phase 1 is to **curate the first 10%** and **design the templates** for the remaining 90%.
3.  **Governance**: The G1-G5 Gates are the "Quality Control" for the data as it trickles in over the next 2 years.
