The Golden Architectural Rule: Strict Decoupling of CMS and Data Catalog

Zero direct database coupling: 100% of frontend dashboards, interactive maps, and calculation widgets must query governed REST/GraphQL endpoints rather than executing raw database queries or embedding static data.

1 System Architecture Tiering & Interface Contracts
  • Tier 1: Presentation Layer (Headless Web CMS): Responsible exclusively for HTML rendering, user interaction, routing, and visual analytics. Consumes dynamic CMS blocks and analytical API payloads. Zero Business Logic Rule: frontend must never perform raw spatial clipping or statistical aggregation client-side.
  • Tier 2: API Gateway & Security Layer: Enforces JSON-Schema payload validation, OAuth2/JWT authentication, rate limiting, and Redis response caching (P95 < 200ms). Exposes versioned endpoints (/api/v1/spatial/risk-profile).
  • Tier 3: Governed Data Platform & Calculation Engine: PostgreSQL 16+ with PostGIS 3.4+ spatial engine implementing the 8 CDM Domains. Background ETL workers (Airflow/Celery) managing automated line-agency ingestion.

Anti-Pattern: The Forbidden "Frankenstein Dashboard"

Hardcoding static data files, CSV tables, or standalone visualization widgets directly into frontend components is strictly prohibited as a catastrophic anti-pattern.

! Failure Mode Analysis & Risks
  • Definition of Anti-Pattern: Embedding local JSON arrays, static GeoJSON files, or CSV dumps inside React/Vue components to rapidly build visual charts or risk maps.
  • 1. Schema Drift & Data Inconsistency: When line agencies (TMD, GISTDA, DDPM) update climate projections or loss records, static components display stale, conflicting numbers.
  • 2. Audit Trail Destruction: UNFCCC A-BTR reporting requires 100% cryptographic provenance tracing back to source agency records. Static files sever this audit link.
  • 3. Mobile Spatial Breakdown: Static GeoJSON bundles bypass PostGIS spatial indexing, crashing client browsers when loading high-density national grids (20,000+ polygons).

Configure PostGIS geometry columns in EPSG:4326, generate Generalized Search Tree (GiST) indexes, and cluster physical table storage by spatial geometry.

1 Spatial Table DDL & GiST Indexing
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE TABLE domain_exp.spatial_unit (
  spatial_unit_id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  spatial_unit_code VARCHAR(16) UNIQUE NOT NULL,
  geom GEOMETRY(MultiPolygon, 4326) NOT NULL
);
CREATE INDEX idx_spatial_unit_geom ON domain_exp.spatial_unit USING GIST(geom);
CLUSTER domain_exp.spatial_unit USING idx_spatial_unit_geom;

-- 5km Hazard Grid (~20,400 Polygons)
CREATE TABLE domain_haz.hazard_map_grid (
  grid_cell_id VARCHAR(32) PRIMARY KEY,
  geom GEOMETRY(Polygon, 4326) NOT NULL
);
CREATE INDEX idx_hazard_map_grid_geom ON domain_haz.hazard_map_grid USING GIST(geom);
2 Spatial Optimization Benchmarks
SELECT su.name_th, AVG(cp.projected_value) AS avg_temp
FROM domain_exp.spatial_unit su
JOIN domain_haz.hazard_map_grid hg ON ST_Intersects(su.geom, hg.geom)
JOIN domain_haz.climate_projection cp ON cp.grid_cell_id = hg.grid_cell_id
WHERE su.parent_code = '5001' AND cp.scenario_code = 'SSP5_85'
GROUP BY su.spatial_unit_code, su.name_th;

  • Vector Tiles: Materialized admin boundary views generate MVTs in < 5 ms.

2 Cryptographic Provenance Engine
def generate_btr_section_export(section_code: str) -> dict:
  records = db.query("""SELECT rs.req_code, eu.evidence_text, qv.numeric_value, eu.source_agency
    FROM requirement_statement rs
    JOIN requirement_evidence_link rel ON rs.req_id = rel.req_id
    JOIN evidence_unit eu ON rel.evidence_id = eu.evidence_id
    LEFT JOIN quantitative_value qv ON eu.evidence_id = qv.evidence_id
    WHERE rs.section_code = :section_code""", {"section_code": section_code})

  # Cryptographic Hash of all raw evidentiary records
  payload_str = json.dumps(records, sort_keys=True)
  prov_hash = hashlib.sha256(payload_str.encode('utf-8')).hexdigest()
