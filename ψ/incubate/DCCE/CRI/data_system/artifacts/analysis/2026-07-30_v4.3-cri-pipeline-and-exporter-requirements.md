## 🚩 Issue #1 (CRITICAL BUG FIX): Rebuild All DDPM-Derived Files with Comma Sanitization

### Problem Statements

1. **Nationwide Uncleaned Comma String Parsing Bug**:
   * Raw Bronze DDPM columns contain numbers with commas (`"3,227"`, `"14,409"`). Calling `pd.to_numeric(errors='coerce')` without `.str.replace(',', '')` dropped all values $\ge 1,000$ as `NaN` (0), corrupting all Silver and Gold DDPM files.

2. **Financial Data Overwrite in `loss_abs.json`**:
   * `tmp_stage1_export.py` replaces absolute financial relief amounts (`197,934,176.28 THB`) with MinMax normalized scores (`1.0`), obliterating raw financial figures from exported JSON payloads.

3. **Single-Year vs Multi-Year Data Leakage**:
   * `period_2567/all/affected_hh_abs.json` looked up `s_affected_hh_abs`, which was missing from `prov_2567_metrics`, falling back to `prov_avg_cri` and leaking the 7-year annualized average (`16,117.17`) directly into the single-year 2567 folder.

4. **Legacy Directory Drift**:
   * `period_2560_2567` (2560–2567) is legacy and must no longer be produced.

### Functional Requirements

1. **REQ-1.1: Complete Rebuild of All DDPM-Derived Files**
   * Create `script/ELT/consolidate_ddpm_master_silver.py` to rebuild `data/1_silver/ddpm/master_village_disaster_stat_2557_2567.csv` from raw Bronze CSV files with strict `parse_clean_numeric()` comma sanitization:
     ```python
     def parse_clean_numeric(series: pd.Series) -> pd.Series:
         """Strips thousand-separator commas and whitespace prior to numeric coercion."""
         return pd.to_numeric(
             series.astype(str).str.replace(",", "").str.strip(),
             errors="coerce"
         ).fillna(0.0)
     ```
   * Execute Gold ELT scripts to rebuild `2_gold/ddpm/fact_ddpm_tambon_impact_climate_yearly_2560_2567.csv`.

2. **REQ-1.2: Preserve Raw Financial & Quantity Metrics in Exporter**
   * Exporter MUST NEVER overwrite `raw_value` with MinMax scores.
   * `loss_abs.json` MUST preserve `raw_value: 197934176.28` for `period_2561_2567` and `6149204.36` for single-year 2567.

3. **REQ-1.3: Column Key Standardization**
   * Update `tmp_stage1_export.py` so metric keys in `prov_2567_metrics` match `h_2567_specs` exactly without falling back to multi-year objects.

4. **REQ-1.4: Deprecate `period_2560_2567` (Legacy Window)**
   * Completely purge `period_2560_2567` generation logic from `tmp_stage1_export.py`.
   * Standardize build outputs exclusively on:
     * `build_exports/stage1/period_2567/` (Single-Year 2567)
     * `build_exports/stage1/period_2561_2567/` (Canonical 7-Year Period: 2561–2567)
