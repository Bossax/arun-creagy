# รายงานแบบจำลองข้อมูลเชิงแนวคิดสำหรับระบบฐานข้อมูลความยืดหยุ่นต่อสภาพภูมิอากาศ

## บทสรุป

แบบจำลองข้อมูลเชิงแนวคิด (Conceptual Data Model: CDM) ของระบบฐานข้อมูลความยืดหยุ่นต่อสภาพภูมิอากาศ (Climate Resilience Database: CRDB) กำหนดโครงสร้างข้อมูลระดับแนวคิดสำหรับเชื่อมข้อมูลภูมิอากาศ ภัย ความเปราะบาง ความเสี่ยง ผลกระทบ ความยืดหยุ่น การปรับตัว และการติดตามผลเข้าด้วยกัน บัญชีรายการหน่วยข้อมูล–คุณลักษณะ–ความสัมพันธ์ (Entity–Attribute–Relationship Catalog: EAR Catalog) รุ่นปัจจุบันประกอบด้วย 8 โดเมนข้อมูล 45 หน่วยข้อมูล และ 51 ความสัมพันธ์

โครงสร้างดังกล่าวแบ่งหน้าที่ในการกำกับข้อมูลตามวงจรงาน ตั้งแต่ข้อมูลนำเข้าทางวิทยาศาสตร์ไปจนถึงผลลัพธ์เชิงนโยบาย พร้อมกำหนดจุดเชื่อมร่วมด้านพื้นที่ เจ้าของข้อมูล ตัวชี้วัด และการมีส่วนสนับสนุนของโครงการ `SPATIAL_UNIT` ทำหน้าที่เป็นจุดอ้างอิงเชิงพื้นที่ `INSTITUTIONAL_BODY` ระบุหน่วยงานบริกรข้อมูลและผู้บริหารโครงการ ส่วน `VULNERABILITY_DETERMINANT` เป็นคลังตัวชี้วัดกลางที่ใช้ร่วมกันในการวิเคราะห์ความเปราะบางและความยืดหยุ่น

CDM ยังแยกข้อมูลที่มีความหมายต่างกันออกเป็นหน่วยข้อมูลเฉพาะ โดเมนความสูญเสียและความเสียหายจึงแยกเหตุการณ์ บริบทการประเมิน ความเสียหายทางกายภาพ ความสูญเสียทางเศรษฐกิจ ความต้องการฟื้นฟู และการระบุสาเหตุออกจากกัน ขณะที่โดเมนการติดตาม ประเมินผล และเรียนรู้เชื่อมผลผลิตระดับโครงการกับผลลัพธ์การปรับตัวระดับพื้นที่ผ่าน `ADAPTATION_PROJECT_OUTCOME_CONTRIBUTION` กลไกเหล่านี้ทำให้กรมฯ สามารถตรวจสอบที่มาของข้อมูลและเชื่อมผลการดำเนินงานกับเป้าหมายด้านความยืดหยุ่นได้

## 1 วัตถุประสงค์และขอบเขต

รายงานนี้อธิบาย CDM ในสามระดับ ได้แก่ โดเมนข้อมูล หน่วยข้อมูล และความสัมพันธ์ โดยใช้ `Domains-v3.csv`, `Entities-v3.csv` และ `Relationships-v4.csv` เป็นแหล่งรายละเอียดหลัก เอกสาร `Pillar_05_CDM_EARCatalog_Deliverable.md` ใช้สำหรับอธิบายเจตนารมณ์ระดับภาพรวมเท่านั้น เนื่องจากชื่อหน่วยข้อมูลและความสัมพันธ์บางรายการในเอกสารดังกล่าวเป็นรุ่นก่อนหน้า

CDM เป็นข้อตกลงด้านความหมายและขอบเขตข้อมูล ไม่ใช่แบบฐานข้อมูลกายภาพ รายงานจึงไม่กำหนดตาราง คอลัมน์ ชนิดข้อมูล หรือคำสั่ง SQL เพิ่มเติมจาก EAR Catalog ชื่อหน่วยข้อมูลภาษาอังกฤษและรหัสโดเมนได้รับการคงไว้เพื่อให้ผู้พัฒนาระบบและเจ้าของข้อมูลตรวจสอบย้อนกลับกับรายการต้นทางได้โดยตรง

## 3 หน่วยข้อมูลในแต่ละโดเมน

### 3.1 โดเมนข้อมูลตัวแปรสำคัญ `DOM_EV`

`DOM_EV` เป็นทะเบียนข้อมูลพื้นฐานทางกายภาพที่ใช้ร่วมกันใน CRDB หน่วยข้อมูลทั้งสามรายการแยกข้อมูลตรวจวัดแบบพลวัต ตัวขับเคลื่อนภูมิอากาศแบบต่อเนื่อง และทะเบียนชุดข้อมูลสิ่งแวดล้อมออกจากกัน การแยกนี้ช่วยให้แบบจำลองภัยเรียกใช้ข้อมูลที่มีรูปแบบและผู้ดูแลต่างกันโดยไม่ต้องขยาย CDM ให้ครอบคลุมตัวแปรวิทยาศาสตร์ทุกชนิดในระดับตาราง

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `METEOROLOGICAL_OBSERVATION` | UUID | ข้อมูลอากาศที่ตรวจวัดจากสถานี ใช้เป็นข้อมูลนำเข้าแบบพลวัต |
| `CLIMATE_DRIVER` | UUID | สภาวะทางกายภาพแบบต่อเนื่องหรือเกิดขึ้นอย่างค่อยเป็นค่อยไป เช่น การเพิ่มขึ้นของระดับน้ำทะเลและอุณหภูมิ |
| `ENVIRONMENTAL_DATA` | UUID | ทะเบียนกลางของชุดข้อมูลสิ่งแวดล้อมกายภาพและเชิงพื้นที่ เช่น ระดับความสูง ดิน ความขรุขระ และน้ำขึ้นน้ำลง |

`ENVIRONMENTAL_DATA` ลดความซ้ำซ้อนจากการสร้างหน่วยข้อมูลเฉพาะสำหรับภูมิประเทศ ดิน อุทกวิทยา และตัวแปรกายภาพแต่ละชนิด หน่วยงานเจ้าของข้อมูลสามารถลงทะเบียนและดูแลชุดข้อมูลผ่าน metadata ขณะที่ CDM คงโครงสร้างระดับแนวคิดให้กระชับ

### 3.2 โดเมนข้อมูลภัยและการสร้างแบบจำลอง `DOM_HAZ`

`DOM_HAZ` เชื่อมสมมติฐานอนาคต ตัวแปรภูมิอากาศ แบบจำลองคำนวณ และผลลัพธ์เชิงพื้นที่เข้าด้วยกัน โดเมนนี้รองรับทั้งการคาดการณ์ล่วงหน้าและการบันทึกเหตุการณ์ที่เกิดขึ้นจริง

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `CLIMATE_SCENARIO` | UUID | เส้นทางอนาคตเชิงสมมติ เช่น SSP5-8.5 ที่ใช้กำหนดเงื่อนไขสำหรับการคาดการณ์ |
| `CLIMATE_PROJECTION` | UUID | ผลคาดการณ์การเปลี่ยนแปลงและดัชนีภูมิอากาศที่สัมพันธ์กับฉากทัศน์ |
| `HAZARDOUS_EVENT` | DDPM_ID | เหตุการณ์ภัยที่เกิดขึ้นจริง เช่น พายุหมุนเขตร้อนหรือภัยแล้ง |
| `HAZARD_MODELS` | UUID | กลไกคำนวณที่จำลองภัยจากตัวขับเคลื่อนภูมิอากาศและข้อมูลสิ่งแวดล้อม |
| `HAZARD_MAP` | UUID | ข้อมูลเชิงพื้นที่ที่แสดงความรุนแรงของภัยจากการจำลองหรือการสังเกตการณ์ |

`HAZARD_MAP` เป็นผลผลิตกลางสำหรับนำข้อมูลภัยไปใช้ในการวิเคราะห์ความเสี่ยง โดยมี `SPATIAL_UNIT` กำหนดขอบเขตพื้นที่ การแยก `CLIMATE_PROJECTION` ออกจาก `HAZARDOUS_EVENT` ช่วยรักษาความแตกต่างระหว่างผลคาดการณ์กับเหตุการณ์ที่เกิดขึ้นจริง

### 3.3 โดเมนข้อมูลความเปราะบางและการเปิดรับภัย `DOM_022`

`DOM_022` กำหนดสิ่งที่อยู่ในพื้นที่เสี่ยงและวิธีอธิบายความเปราะบางของสิ่งนั้น โครงสร้างแบ่งข้อมูลออกเป็นหน่วยพื้นที่ ทรัพย์สิน กรอบวิธีวิทยา มิติ ตัวแปร และฟังก์ชันผลกระทบ เพื่อรองรับทั้งการวิเคราะห์ด้วยดัชนีและการคำนวณด้วยเส้นโค้งความเสียหาย

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `SPATIAL_UNIT` | UUID | หน่วยเรขาคณิตพื้นฐาน เช่น เขตการปกครอง เขตสำมะโน หรือลุ่มน้ำ |
| `EXPOSED_ASSET` | UUID | ประชาชน อาคาร หรือพืชผลที่ตั้งอยู่ในพื้นที่เสี่ยงภัย |
| `VULNERABILITY_FRAMEWORK` | UUID | กรอบวิธีวิทยาสำหรับสร้างแบบจำลองความเปราะบาง |
| `VULNERABILITY_DIMENSION` | UUID | องค์ประกอบของความเปราะบาง เช่น ความอ่อนไหวและศักยภาพในการปรับตัว |
| `VULNERABILITY_STRUCTURE` | UUID | ตรรกะการจับคู่ตัวแปรและการให้น้ำหนักกับองค์ประกอบความเปราะบาง |
| `IMPACT_FUNCTION` | UUID | เส้นโค้งทางคณิตศาสตร์ที่เชื่อมระดับความรุนแรงของภัยกับสัดส่วนความเสียหาย |
| `VULNERABILITY_DETERMINANT` | UUID | ตัวชี้วัดทางสังคมหรือเศรษฐกิจที่เป็นกลางและใช้เป็นตัวแปรของแบบจำลอง |

`VULNERABILITY_DETERMINANT` ไม่กำหนดบทบาทของตัวชี้วัดไว้ตายตัว `VULNERABILITY_STRUCTURE` เป็นผู้กำหนดว่าตัวชี้วัดแต่ละรายการทำหน้าที่อย่างไรภายใต้กรอบวิธีวิทยาหนึ่ง วิธีนี้ทำให้ตัวชี้วัดเดียวกันสามารถใช้ในกรอบที่มีแนวคิดหรือการให้น้ำหนักต่างกันได้

### 3.4 โดเมนข้อมูลการวิเคราะห์ความเสี่ยง `DOM_023`

`DOM_023` บันทึกการคำนวณความเสี่ยงและผลลัพธ์จากการคำนวณ หน่วยข้อมูล `RISK_ANALYSIS` รองรับทั้งการวิเคราะห์เชิงความน่าจะเป็นและการวิเคราะห์แบบดัชนี จึงแยกผลลัพธ์ออกเป็นค่าความเสี่ยงที่มีหน่วยและคะแนนดัชนีที่ไม่มีหน่วย

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `RISK_ANALYSIS` | UUID | การคำนวณความเสี่ยงหนึ่งครั้งในรูปแบบเชิงความน่าจะเป็นหรือแบบดัชนี |
| `RISK_METRIC` | UUID | ผลลัพธ์เชิงปริมาณจากการวิเคราะห์ความเสี่ยง เช่น มูลค่าความสูญเสียคาดหมายรายปี |
| `COMPOSITE_INDEX` | UUID | คะแนนเชิงปริมาณสำหรับความเสี่ยง ความยืดหยุ่น หรือแบบจำลองที่ใช้ดัชนี |

การแยก `RISK_METRIC` ออกจาก `COMPOSITE_INDEX` ป้องกันการตีความคะแนนมาตรฐานเสมือนเป็นค่าความเสียหายทางเศรษฐกิจ และทำให้บริการข้อมูลระบุหน่วยวัดกับวิธีคำนวณได้ชัดเจน

### 3.5 โดเมนข้อมูลภัยพิบัติและผลกระทบ `DOM_024`

`DOM_024` ใช้โครงสร้างข้อมูลความสูญเสียและความเสียหายสามชั้น ชั้นเหตุการณ์กำหนดเหตุการณ์และพื้นที่ ชั้นบริบทการประเมินแยกระยะเวลา หน่วยงานนำ และสถานะการทบทวน ส่วนชั้นมูลค่ารายละเอียดแยกความเสียหายทางกายภาพ ความสูญเสียทางเศรษฐกิจ และความต้องการฟื้นฟู โครงสร้างนี้ป้องกันการรวมค่าต่างประเภทไว้ในระเบียนเดียว

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `DISASTER_EVENT` | VARCHAR | เหตุการณ์ภัยที่เกิดขึ้นจริงหนึ่งครั้งและก่อให้เกิดภัยพิบัติ ทำหน้าที่เป็นหลักยึดของชั้นเหตุการณ์ |
| `EVENT_LOCATION` | VARCHAR | รายละเอียดพื้นที่ที่เชื่อมเหตุการณ์หนึ่งครั้งกับหลายหน่วยการปกครอง |
| `ASSESSMENT_CONTEXT` | VARCHAR | metadata เชื่อมระยะการประเมิน หน่วยงานนำ สถานะการทบทวน และวันที่ประเมิน |
| `LD_PHYSICAL_DAMAGE` | VARCHAR | ระเบียนมูลค่าความเสียหายทางกายภาพรายภาคส่วนสำหรับทรัพย์สินที่เสียหายหรือถูกทำลาย |
| `LD_ECONOMIC_LOSS` | VARCHAR | ระเบียนการหยุดชะงักของกระแสเศรษฐกิจรายภาคส่วน เช่น รายได้หรือผลผลิตที่สูญเสียไป |
| `LD_RECOVERY_RECONSTRUCTION_NEEDS` | VARCHAR | ความต้องการเงินทุนหลังการประเมินสำหรับการฟื้นฟูและการบูรณะ |
| `ENVIRONMENTAL_LOSS_RECORD` | UUID | ระเบียนความสูญเสียของระบบนิเวศ เช่น พื้นที่ป่าถูกไฟไหม้หรือพื้นที่ปะการังฟอกขาว |
| `RELIEF_PAYMENT_RECORD` | UUID | ระเบียนเงินช่วยเหลือฉุกเฉินและเงินชดเชย |
| `ATTRIBUTION_LINK` | UUID | หน่วยข้อมูลเชื่อมโยงที่ยืนยันความสัมพันธ์เชิงสาเหตุระหว่างความสูญเสียกับตัวขับเคลื่อนภูมิอากาศหรือปัจจัยความเปราะบาง |

`ASSESSMENT_CONTEXT` ช่วยแยกข้อมูลรายงานเร่งด่วนออกจากผลประเมินหลังเกิดภัยที่ผ่านการตรวจสอบแล้ว ส่วน `ATTRIBUTION_LINK` ทำให้การระบุสาเหตุเป็นข้อมูลที่มีโครงสร้างและตรวจสอบย้อนกลับได้ แทนการฝังข้อสรุปเชิงสาเหตุไว้ในข้อความอิสระ

### 3.6 โดเมนข้อมูลการประเมินความยืดหยุ่น `DOM_030`

`DOM_030` แยกกรอบวิธีวิทยา องค์ประกอบ ตรรกะการให้น้ำหนัก และการประเมินจริงออกจากกัน โครงสร้างนี้ทำให้กรมฯ เปรียบเทียบผลการประเมินหลายช่วงเวลาหรือหลายพื้นที่ภายใต้กรอบเดียวกันได้ และสามารถปรับวิธีให้น้ำหนักโดยไม่แก้ข้อมูลตัวชี้วัดต้นทาง

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `RESILIENCE_FRAMEWORK` | UUID | กรอบวิธีวิทยาสำหรับประเมินความยืดหยุ่น |
| `RESILIENCE_DIMENSION` | UUID | องค์ประกอบเชิงประเด็น เช่น สังคม เศรษฐกิจ และสถาบัน ที่ใช้กำหนดความยืดหยุ่น |
| `RESILIENCE_STRUCTURE` | UUID | ตรรกะการให้น้ำหนักและรวมคะแนนของแต่ละองค์ประกอบความยืดหยุ่น |
| `RESILIENCE_ASSESSMENT` | UUID | การนำกรอบวิธีวิทยาไปใช้กับหน่วยพื้นที่เพื่อสร้างค่าดัชนี |

`RESILIENCE_STRUCTURE` ใช้ตัวแปรจาก `VULNERABILITY_DETERMINANT` ร่วมกับโดเมนความเปราะบาง ทำให้ตัวชี้วัดทางสังคมและเศรษฐกิจมีทะเบียนกลางและลดการสร้างตัวแปรซ้ำสำหรับแต่ละแบบประเมิน

### 3.7 โดเมนข้อมูลการวางแผนการปรับตัว `DOM_040`

`DOM_040` จัดเก็บบริบทที่ใช้ตัดสินใจ ชุดทางเลือก กระบวนการประเมิน และโครงการที่นำไปดำเนินการ หน่วยข้อมูลในโดเมนนี้ช่วยให้กรมฯ ตรวจสอบได้ว่าโครงการหนึ่งเกิดจากปัญหาและทางเลือกใด ผ่านการประเมินด้วยเกณฑ์ใด และมีหน่วยงานใดเป็นผู้รับผิดชอบ

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `DECISION_CONTEXT` | UUID | ขอบเขตปัญหา เงื่อนไข และระดับความไม่แน่นอนสำหรับการวางแผนปรับตัว |
| `INSTITUTIONAL_BODY` | UUID | หน่วยงานภาครัฐและผู้ประสานงานที่ทำหน้าที่เป็นบริกรข้อมูลหรือผู้บริหารโครงการ |
| `ADAPTATION_PORTFOLIO` | UUID | กลุ่มทางเลือกการปรับตัวหลายรายการสำหรับประเมินร่วมกัน |
| `ADAPTATION_OPTION` | UUID | แนวทางแก้ไขมาตรฐานจากคลังทางเลือกการปรับตัว |
| `APPRAISAL_EVENT` | UUID | เหตุการณ์หรือรอบการประเมินทางเลือกการปรับตัว |
| `APPRAISAL_METRIC` | UUID | ค่าหรือเกณฑ์รายละเอียดที่เป็นผลจากการประเมินทางเลือก |
| `ADAPTATION_PROJECT` | UUID | การนำมาตรการปรับตัวไปดำเนินการจริงภายใต้ขอบเขตทรัพยากรที่กำหนด |

`DECISION_CONTEXT` เชื่อมความต้องการเชิงนโยบายกับชุดทางเลือก ขณะที่ `APPRAISAL_EVENT` และ `APPRAISAL_METRIC` เก็บหลักฐานการพิจารณาก่อนเลือกมาตรการไปดำเนินการเป็น `ADAPTATION_PROJECT`

### 3.8 โดเมนข้อมูลการติดตาม ประเมินผล และเรียนรู้ `DOM_050`

`DOM_050` ติดตามผลการดำเนินงานและทรัพยากรของโครงการปรับตัว โดยแยกผลผลิตที่นับได้ออกจากผลลัพธ์เชิงระบบ พร้อมเชื่อมงบประมาณ แหล่งเงินทุน และการสนับสนุนระหว่างประเทศกับโครงการที่เกี่ยวข้อง

| หน่วยข้อมูล | คีย์หลัก | คำอธิบาย |
| --- | --- | --- |
| `ADAPTATION_OUTPUT` | UUID | ผลผลิตระดับโครงการที่กำหนดแบบ SMART เช่น ความยาวกำแพงป้องกันน้ำหรือจำนวนการอบรมชุมชน |
| `ADAPTATION_OUTCOME` | UUID | การเปลี่ยนแปลงด้านความยืดหยุ่นและตัวชี้วัดความก้าวหน้าที่เชื่อมกับเป้าหมายระดับระบบ |
| `ADAPTATION_PROJECT_OUTCOME_CONTRIBUTION` | UUID | หน่วยข้อมูลเชื่อมโยงระหว่างโครงการกับผลลัพธ์การปรับตัวระดับระบบที่โครงการมีส่วนสนับสนุน |
| `BUDGET_TAG_RECORD` | UUID | ระเบียนการติดป้ายงบประมาณด้านภูมิอากาศภายในประเทศที่เชื่อมกับโครงการ |
| `SUPPORT_TRACKING_RECORD` | UUID | ระเบียนการสนับสนุนระหว่างประเทศด้านการเงิน เทคโนโลยี หรือการเสริมสร้างศักยภาพ |
| `FUNDING_SOURCE` | UUID | แหล่งที่มาของเงินทุนสำหรับโครงการปรับตัว |
| `RISK_TOLERANCE_PROFILE` | UUID | ระดับความเสี่ยงที่ผู้มีส่วนได้ส่วนเสียยอมรับได้เพื่อใช้กำกับการตัดสินใจ |

`ADAPTATION_PROJECT_OUTCOME_CONTRIBUTION` แก้ความต่างของระดับข้อมูลระหว่างผลผลิตของโครงการกับผลลัพธ์ระดับพื้นที่ โครงการหลายรายการสามารถมีส่วนสนับสนุนผลลัพธ์เดียวกัน และกรมฯ สามารถรักษาหลักฐานของการมีส่วนสนับสนุนแต่ละรายการแยกจากค่าผลลัพธ์รวม

## 4 ความสัมพันธ์ระหว่างหน่วยข้อมูล

ความสัมพันธ์ 51 รายการกำหนดทิศทางการอ้างอิงและจำนวนระเบียนที่เชื่อมกัน เครื่องหมาย `1:N` หมายถึงระเบียนต้นทางหนึ่งรายการเชื่อมกับระเบียนปลายทางได้หลายรายการ `N:1` หมายถึงระเบียนต้นทางหลายรายการอ้างอิงระเบียนปลายทางร่วมกัน และ `N:M` หมายถึงทั้งสองด้านเชื่อมกันได้หลายรายการ การนำ CDM ไปพัฒนาเป็นแบบข้อมูลเชิงตรรกะต้องกำหนดคีย์อ้างอิงและหน่วยข้อมูลเชื่อมโยงให้รองรับ cardinality เหล่านี้

### 4.1 ความสัมพันธ์ด้านพื้นที่ ภูมิอากาศ และภัย

`SPATIAL_UNIT` เป็นจุดอ้างอิงร่วมของข้อมูลตรวจวัด ตัวขับเคลื่อนภูมิอากาศ ชุดข้อมูลสิ่งแวดล้อม การคาดการณ์ และแผนที่ภัย ความสัมพันธ์นี้ทำให้ข้อมูลที่มาจากหน่วยงานหรือแบบจำลองต่างกันสามารถค้นหาและเปรียบเทียบภายใต้ขอบเขตพื้นที่เดียวกันได้

| ลำดับ | หน่วยข้อมูลต้นทาง | หน่วยข้อมูลปลายทาง | Cardinality | กฎทางธุรกิจ |
| ---: | --- | --- | :---: | --- |
| 1 | `SPATIAL_UNIT` | `METEOROLOGICAL_OBSERVATION` | 1:N | หน่วยพื้นที่เป็นหลักยึดของข้อมูลอุตุนิยมวิทยาที่ตรวจวัดได้ |
| 2 | `SPATIAL_UNIT` | `CLIMATE_DRIVER` | 1:N | หน่วยพื้นที่เป็นหลักยึดของข้อมูลตัวขับเคลื่อนภูมิอากาศที่เกิดขึ้นอย่างค่อยเป็นค่อยไป |
| 3 | `SPATIAL_UNIT` | `ENVIRONMENTAL_DATA` | 1:N | หน่วยพื้นที่เป็นหลักยึดของชุดข้อมูลสิ่งแวดล้อมกายภาพที่ลงทะเบียนไว้ |
| 4 | `INSTITUTIONAL_BODY` | `ENVIRONMENTAL_DATA` | 1:N | หน่วยงานทำหน้าที่เป็นผู้ดูแลและผู้จัดการชุดข้อมูลสิ่งแวดล้อม |
| 5 | `CLIMATE_SCENARIO` | `CLIMATE_PROJECTION` | 1:N | ฉากทัศน์ภูมิอากาศหนึ่งรายการกำหนดผลคาดการณ์ได้หลายตัวแปร |
| 6 | `CLIMATE_DRIVER` | `CLIMATE_PROJECTION` | 1:N | ตัวขับเคลื่อนภูมิอากาศเป็นตัวแปรฐานสำหรับผลคาดการณ์อนาคต |
| 7 | `SPATIAL_UNIT` | `CLIMATE_PROJECTION` | 1:N | ผลคาดการณ์อนาคตแต่ละรายการต้องมีขอบเขตเชิงพื้นที่ |
| 8 | `ENVIRONMENTAL_DATA` | `HAZARD_MODELS` | N:M | แบบจำลองภัยใช้ตัวแปรสิ่งแวดล้อมหลายชนิด และชุดข้อมูลหนึ่งรายการใช้ได้กับหลายแบบจำลอง |
| 9 | `CLIMATE_DRIVER` | `HAZARD_MODELS` | 1:N | ตัวขับเคลื่อนภูมิอากาศทำหน้าที่เป็นข้อมูลบังคับสำหรับแบบจำลองคำนวณ |
| 10 | `HAZARD_MODELS` | `HAZARD_MAP` | 1:N | แบบจำลองหนึ่งรายการสร้างแผนที่ความรุนแรงและขอบเขตภัยได้หลายรายการ |
| 11 | `SPATIAL_UNIT` | `HAZARD_MAP` | 1:N | แผนที่ภัยแต่ละรายการต้องเชื่อมกับหน่วยพื้นที่ |

ความสัมพันธ์ `ENVIRONMENTAL_DATA` กับ `HAZARD_MODELS` เป็นความสัมพันธ์หลายต่อหลาย เนื่องจากแบบจำลองหนึ่งอาจใช้ข้อมูลระดับความสูง ดิน ความขรุขระ และข้อมูลน้ำพร้อมกัน ขณะที่ชุดข้อมูลเดียวกันอาจสนับสนุนการจำลองภัยหลายประเภท การพัฒนาแบบข้อมูลเชิงตรรกะจึงต้องมีตารางเชื่อมพร้อมบทบาทของข้อมูล รุ่นข้อมูล และเงื่อนไขการใช้งาน

### 4.2 ความสัมพันธ์ด้านการเปิดรับภัย ความเปราะบาง และความเสี่ยง

กลุ่มความสัมพันธ์นี้เชื่อมทรัพย์สินกับพื้นที่ กำหนดโครงสร้างของกรอบความเปราะบาง และบันทึกผลลัพธ์จากการวิเคราะห์ความเสี่ยง `VULNERABILITY_DETERMINANT` ทำหน้าที่เป็นข้อมูลตัวชี้วัดกลาง ส่วนกรอบ มิติ และโครงสร้างเป็นผู้กำหนดความหมายกับน้ำหนักของตัวชี้วัดในแต่ละวิธีวิทยา

| ลำดับ | หน่วยข้อมูลต้นทาง | หน่วยข้อมูลปลายทาง | Cardinality | กฎทางธุรกิจ |
| ---: | --- | --- | :---: | --- |
| 12 | `SPATIAL_UNIT` | `EXPOSED_ASSET` | 1:N | ขอบเขตการปกครองหรือขอบเขตเชิงพื้นที่หนึ่งแห่งมีทรัพย์สินที่เปิดรับภัยได้หลายรายการ |
| 13 | `VULNERABILITY_FRAMEWORK` | `VULNERABILITY_DIMENSION` | 1:N | กรอบความเปราะบางหนึ่งกรอบประกอบด้วยองค์ประกอบหลายด้าน เช่น ความอ่อนไหว |
| 14 | `VULNERABILITY_DIMENSION` | `VULNERABILITY_STRUCTURE` | 1:N | องค์ประกอบหนึ่งด้านกำหนดตรรกะการให้น้ำหนักและการจับคู่ตัวแปรได้หลายรายการ |
| 15 | `VULNERABILITY_STRUCTURE` | `VULNERABILITY_DETERMINANT` | N:1 | โครงสร้างหลายรายการสามารถอ้างอิงตัวชี้วัดที่เป็นกลางรายการเดียวกันจากคลังกลาง |
| 16 | `VULNERABILITY_FRAMEWORK` | `IMPACT_FUNCTION` | 1:N | กรอบความเปราะบางหนึ่งกรอบกำหนดเส้นโค้งคณิตศาสตร์สำหรับเชื่อมความรุนแรงของภัยกับความเสียหายได้หลายรายการ |
| 17 | `RISK_ANALYSIS` | `RISK_METRIC` | 1:N | การวิเคราะห์หนึ่งครั้งสร้างค่าความเสี่ยงเชิงปริมาณได้หลายรายการ |
| 18 | `RISK_ANALYSIS` | `COMPOSITE_INDEX` | 1:N | การวิเคราะห์หนึ่งครั้งสร้างคะแนนนโยบายหรือค่าดัชนีได้หลายรายการ |
| 19 | `SPATIAL_UNIT` | `RISK_ANALYSIS` | 1:N | หน่วยพื้นที่หนึ่งแห่งรองรับการคำนวณความเสี่ยงได้หลายครั้งหรือหลายวิธี |

## 5 การเชื่อมโยงข้ามโดเมนข้อมูล

CDM เชื่อมวงจรข้อมูลของ CRDB ผ่านจุดอ้างอิงและหน่วยข้อมูลสำคัญห้ากลุ่ม

1. **พื้นที่** `SPATIAL_UNIT` เชื่อมข้อมูลตรวจวัด ตัวขับเคลื่อนภูมิอากาศ ชุดข้อมูลสิ่งแวดล้อม ผลคาดการณ์ แผนที่ภัย ทรัพย์สิน เหตุการณ์ภัยพิบัติ การวิเคราะห์ความเสี่ยง การประเมินความยืดหยุ่น และผลลัพธ์การปรับตัว พื้นที่จึงเป็นมิติร่วมสำหรับค้นหา เปรียบเทียบ และรวมข้อมูล
2. **เจ้าของและผู้รับผิดชอบ** `INSTITUTIONAL_BODY` เชื่อมหน่วยงานบริกรชุดข้อมูลสิ่งแวดล้อมกับหน่วยงานผู้บริหารโครงการปรับตัว ทำให้หน้าที่กำกับข้อมูลและการดำเนินงานอยู่ในโครงสร้างเดียวกัน
3. **ตัวชี้วัดร่วม** `VULNERABILITY_DETERMINANT` เป็นคลังตัวชี้วัดกลางที่ใช้ได้ทั้งใน `VULNERABILITY_STRUCTURE` และ `RESILIENCE_STRUCTURE` กรอบวิธีวิทยาเป็นผู้กำหนดบทบาทและน้ำหนักของตัวชี้วัดแต่ละรายการ
4. **การระบุสาเหตุ** `ATTRIBUTION_LINK` เชื่อมเหตุการณ์ภัยพิบัติกับตัวขับเคลื่อนภูมิอากาศ ทำให้ข้อสรุปเรื่องสาเหตุมีระเบียนและตรวจสอบย้อนกลับได้
5. **การเชื่อมผลผลิตกับผลลัพธ์** `ADAPTATION_PROJECT_OUTCOME_CONTRIBUTION` เชื่อมโครงการกับผลลัพธ์การปรับตัวระดับพื้นที่ ช่วยแยกการส่งมอบผลผลิตออกจากการเปลี่ยนแปลงเชิงระบบ พร้อมเก็บหลักฐานการมีส่วนสนับสนุนของแต่ละโครงการ

เมื่อพิจารณาตามลำดับการใช้ข้อมูล ข้อมูลตรวจวัด ตัวขับเคลื่อนภูมิอากาศ และข้อมูลสิ่งแวดล้อมสนับสนุนการสร้างผลคาดการณ์และแผนที่ภัย ข้อมูลพื้นที่ ทรัพย์สิน และความเปราะบางสนับสนุนการวิเคราะห์ความเสี่ยง เหตุการณ์ที่เกิดขึ้นจริงเชื่อมกับระเบียนความเสียหายและการระบุสาเหตุ ผลการวิเคราะห์กับผลการประเมินความยืดหยุ่นสนับสนุนการกำหนดบริบทและทางเลือกการปรับตัว และข้อมูลโครงการเชื่อมไปยังผลผลิต ผลลัพธ์ งบประมาณ เงินทุน และการสนับสนุน

## 6 ประโยชน์ต่อการพัฒนาระบบข้อมูลของกรมฯ

CDM กำหนดภาษากลางสำหรับเจ้าของข้อมูล นักวิเคราะห์ และผู้พัฒนาระบบ ชื่อหน่วยข้อมูลและความสัมพันธ์ช่วยให้แต่ละฝ่ายระบุได้ว่าข้อมูลหนึ่งรายการหมายถึงอะไร อยู่ภายใต้โดเมนใด ใครรับผิดชอบ และต้องเชื่อมกับข้อมูลใดก่อนนำไปใช้

กรมฯ สามารถใช้ EAR Catalog เป็นฐานสำหรับพัฒนาแบบข้อมูลเชิงตรรกะ พจนานุกรมข้อมูล ข้อกำหนด API และกฎตรวจสอบคุณภาพข้อมูล การพัฒนาระยะถัดไปควรรักษา `Domain_ID`, `Entity_Name`, `Term_ID` และ cardinality เป็นรหัสอ้างอิงร่วม พร้อมกำหนดคีย์อ้างอิง หน่วยข้อมูลเชื่อมโยง และเงื่อนไขบังคับให้สอดคล้องกับกฎทางธุรกิจทั้ง 51 รายการ

โครงสร้างความสูญเสียและความเสียหายต้องรักษาความแตกต่างระหว่างความเสียหายทางกายภาพ ความสูญเสียทางเศรษฐกิจ และความต้องการฟื้นฟู ส่วนระบบติดตามการปรับตัวต้องรักษาความแตกต่างระหว่างผลผลิตของโครงการกับผลลัพธ์ระดับพื้นที่ หลักการสองประการนี้มีผลโดยตรงต่อความถูกต้องของการรายงานและการประเมินประสิทธิผลของมาตรการปรับตัว

โดยสรุป CDM ปัจจุบันทำหน้าที่เป็นโครงสร้างกำกับความหมายของข้อมูล CRDB ครอบคลุมตั้งแต่ฐานข้อมูลวิทยาศาสตร์ไปจนถึงผลลัพธ์เชิงนโยบาย จุดอ้างอิงด้านพื้นที่ เจ้าของข้อมูล ตัวชี้วัด และหน่วยข้อมูลเชื่อมโยงทำให้ข้อมูลจากหลายหน่วยงานรวมกันได้โดยยังคงบริบท ความรับผิดชอบ และเส้นทางการตรวจสอบย้อนกลับ
