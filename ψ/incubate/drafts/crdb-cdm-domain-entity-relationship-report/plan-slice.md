# ข้อตกลงสำหรับรายงาน CDM ภาษาไทย

## หน้าที่ของรายงาน

อธิบาย CDM ของระบบ CRDB ผ่านสามระดับ ได้แก่ โดเมนข้อมูล หน่วยข้อมูล และความสัมพันธ์ เพื่อให้ผู้อ่านเข้าใจทั้งการแบ่งเขตข้อมูลและการเชื่อมโยงข้อมูลข้ามโดเมน

## โครงสร้างที่อนุมัติ

1. วัตถุประสงค์และบทบาทของ CDM
2. ภาพรวมและหน้าที่ของแต่ละโดเมนข้อมูล
3. หน่วยข้อมูลสำคัญภายในแต่ละโดเมน
4. ความสัมพันธ์ภายในโดเมนและข้ามโดเมน
5. ภาพรวมการไหลของข้อมูลและประโยชน์ต่อระบบข้อมูลของกรมฯ
6. ตารางสรุปโดเมนข้อมูล–หน่วยข้อมูล–ความสัมพันธ์

## ฐานหลักฐานและลำดับความสำคัญ

1. `Domains-v3.csv` เป็นแหล่งอ้างอิงหลักสำหรับ 8 โดเมน ชื่อ เจ้าของ และตรรกะหลัก
2. `Entities-v3.csv` เป็นแหล่งอ้างอิงหลักสำหรับ 45 หน่วยข้อมูล ประเภทคีย์ คำจำกัดความ และหมายเหตุ
3. `Relationships-v4.csv` เป็นแหล่งอ้างอิงหลักสำหรับ 51 ความสัมพันธ์ cardinality และกฎทางธุรกิจ
4. `Pillar_05_CDM_EARCatalog_Deliverable.md` ใช้เฉพาะโครงและเหตุผลเชิงสถาปัตยกรรม เนื่องจากชื่อหน่วยข้อมูลบางส่วนเป็นรุ่นก่อน
5. trace วันที่ 13 กรกฎาคม 2569 ใช้อธิบายการตัดสินใจเรื่อง `ENVIRONMENTAL_DATA`, แบบจำลองข้อมูลความสูญเสียและความเสียหายสามชั้น และสะพานเชื่อมผลผลิตกับผลลัพธ์การปรับตัว

## ข้อเท็จจริงระดับภาพรวม

- CDM ปัจจุบันประกอบด้วย 8 โดเมนข้อมูล 45 หน่วยข้อมูล และ 51 ความสัมพันธ์
- จำนวนหน่วยข้อมูลรายโดเมน ได้แก่ DOM_EV 3, DOM_HAZ 5, DOM_022 7, DOM_023 3, DOM_024 9, DOM_030 4, DOM_040 7 และ DOM_050 7
- `SPATIAL_UNIT` เป็นจุดอ้างอิงเชิงพื้นที่ร่วมของข้อมูลอุตุนิยมวิทยา ตัวขับเคลื่อนภูมิอากาศ ข้อมูลสิ่งแวดล้อม การคาดการณ์ แผนที่ภัย ทรัพย์สิน เหตุการณ์ภัยพิบัติ การวิเคราะห์ความเสี่ยง การประเมินความยืดหยุ่น และผลลัพธ์การปรับตัว
- `INSTITUTIONAL_BODY` เชื่อมการกำกับดูแลข้อมูลสิ่งแวดล้อมกับการบริหารโครงการปรับตัว
- `VULNERABILITY_DETERMINANT` เป็นคลังตัวชี้วัดกลางที่ใช้ร่วมกันในตรรกะความเปราะบางและความยืดหยุ่น
- `ADAPTATION_PROJECT_OUTCOME_CONTRIBUTION` เป็นหน่วยข้อมูลเชื่อมโยงที่แก้ความไม่สอดคล้องระหว่างผลผลิตระดับโครงการกับผลลัพธ์การปรับตัวระดับพื้นที่หรือระบบ

## กติกาการเขียน

- ใช้ภาษาไทยทางการและอธิบายความหมายเชิงหน้าที่ก่อนรายละเอียดทางเทคนิค
- ใช้คำว่า “หน่วยข้อมูล” แทน Entity ในเนื้อหาภาษาไทย และคงรหัสกับ `Entity_Name` ภาษาอังกฤษในรูปแบบ code
- ใช้คำว่า “โดเมนข้อมูล” หรือ “เขตข้อมูล” ตามบริบท และไม่ใช้คำว่า “สายข้อมูล”
- ใช้ “คณะที่ปรึกษา” สำหรับการวิเคราะห์และการออกแบบ และ “กรมฯ” สำหรับเจ้าของระบบหรือการนำไปใช้
- ไม่เพิ่ม cardinality หรือความสัมพันธ์ที่ไม่มีใน `Relationships-v4.csv`
- ระบุข้อจำกัดของแหล่งข้อมูลเมื่อจำเป็น โดยไม่ปะปนรายการจากคนละรุ่น
