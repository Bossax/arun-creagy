# Lesson: an excluded framing device needs a replacement, not a compression

**Context**: Drafting CRDB exec-summary §2.1 via `/writing-th`. The writing plan's exec-summary spec excludes "รายละเอียดกรอบ IPCC" (IPCC framework detail) from the summary version, while the full-report spec names the IPCC risk chain explicitly. My first content contract for the exec-summary section still framed the inclusion criteria around IPCC — just without listing all 8 chain elements — reading the exclusion as "don't over-explain it" rather than "don't use it at all."

**What happened**: Boss corrected this directly: the exec summary shouldn't mention IPCC at all, because the risk ontology is already embedded in the Conceptual Data Model's data domains (`cdm_sub_domain` in particular). The section needed a genuinely different explanatory device — CDM domains — not a lighter version of the excluded one.

**Lesson**: When a writing plan excludes a framing device from one deliverable variant (e.g., a summary) that a sibling variant (e.g., the full report) uses explicitly, don't default to compressing that same device. Ask what should replace it as the reader-facing explanation — the plan author may have a specific alternate framing in mind that only surfaces if asked, not inferred from the exclusion list alone.

**How to apply**: At the content-contract stage (`/writing-th` Gate 2), when an exclusion removes a framework/device the source material leans on, explicitly flag in the contract summary what's replacing it and ask the human to confirm — rather than silently substituting a compressed version of the excluded device.
