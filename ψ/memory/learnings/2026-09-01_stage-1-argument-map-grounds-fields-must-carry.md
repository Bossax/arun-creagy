# Stage 1 (argument-map) `grounds` fields must carry full supporting detail — conc

Stage 1 (argument-map) `grounds` fields must carry full supporting detail — concrete numbers, findings, framework contents, specific design rationale — not a compressed core claim. The two-lane drafting split (Lane A: word-for-word polish of existing full-report-altitude prose; Lane B: verbalize new content from the approved argument map) fixed Lane A's fidelity loss, but Lane B still verbalizes purely from `grounds`. If `grounds` is written as a condensed restatement of the claim rather than real supporting material, Stage 3 has nothing to expand from and produces thin paragraphs. This is a distinct failure mode from the raw-source-reopening risk the two-lane split was designed to prevent. The fix belongs upstream, at Stage 1 — enrich `grounds` with real supporting detail, which still passes through the Stage 2 human approval gate before reaching verbalization — not by giving Stage 3 renewed access to raw sources. Apply this whenever a topic is mostly Lane B (thin or no existing full-report-level source prose, so most content must be freshly synthesized), e.g. CRDB full-report §2.3.
