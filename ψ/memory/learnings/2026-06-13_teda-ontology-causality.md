# Redefining Causality: The Shift from T-E-CH-D to T-E-D-A

## Context
While auditing the Climate Risk Index (CRI) history, the Oracle struggled to distinguish between the "process of discovery" and the "motive for change." This resulted in redundant ledger entries where a single file was logged as both a Trigger and Evidence.

## The Pattern: Motive vs. Artifact
The Oracle philosophy demands that **Files are not Triggers; Files are Evidence.** 
- **Evidence (E)**: The physical "Nouns" (e.g., `app.py`, `transcript.pdf`).
- **Trigger (T)**: The conceptual "Verbs" or insights derived from evidence (e.g., "Stakeholder needs regional benchmarking").

By separating the **Motive** (Trigger) from the **Artifact** (Evidence), we eliminate database normalization errors in markdown and create a cleaner causal chain.

## The Upgrade: T-E-D-A Ontology
The legacy T-E-CH-D framework was upgraded to **Trigger &rarr; Evidence &rarr; Decision &rarr; Asset**:
1.  **Trigger (T)**: The kinetic insight or mandate.
2.  **Evidence (E)**: The physical grounding artifacts.
3.  **Decision (D)**: The Semantic Lock (Agreed-upon posture).
4.  **Asset (A)**: The hardened technical reality.

## Implementation: Lens & Funnel
Discovery skills (`/trace`) should act as a **Lens**, outputting unstructured hypotheses. Commitment skills (`/seal`) should act as a **Funnel**, consuming those hypotheses and hardening them into the project spine via database-level bonding (`arra_trace_link`).

## Lesson Learned
Strategic documentation is most effective when it mirrors the engineering lifecycle. Moving from "Change" (a verb) to "Decision" (a state) and "Deliverable" (management-speak) to "Asset" (technical-speak) aligns the Oracle more closely with technical reality and the Semantic Lock mandate.
