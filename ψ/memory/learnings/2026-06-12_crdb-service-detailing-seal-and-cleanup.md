# Lesson Learned — Service Detailing Requires Explicit Product Scope

When DCCE moves from service intelligence to service detailing, the output must change from narrative descriptions to executable dossiers. A service should declare its decision problem, priority use cases, target agencies, minimum viable package, data and method dependencies, governance roles, asset lifecycle, and adoption test. The Loss & Damage example showed that use cases become useful only when clustered into a reusable service capability with a clear operational boundary.
