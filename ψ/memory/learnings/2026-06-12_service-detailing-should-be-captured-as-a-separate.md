# Service-detailing should be captured as a separate learning artifact when a proj

Service-detailing should be captured as a separate learning artifact when a project moves from service intelligence to actionable product scope. The useful pattern is to split the work into: (1) conceptual model that explains the abstraction, (2) concrete alpha-service example that proves the abstraction, (3) service-detailing execution plan that turns the abstraction into dossiers, and (4) seal-chain entries that keep evidence, trigger, change, and deliverables traceable. This separation prevents the retro, the seal, and the retro write-up from collapsing into one ambiguous step and makes the work easier to govern and archive.
