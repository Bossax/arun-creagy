# Independent review catches what self-review misses, even when the drafting agent is being careful

When resolving Boss's inline `%%` corrections on exec-summary sections 1.2-1.4 and running them through writing-th v5, the drafting agent (me) made every fix carefully, cross-checked against evidence sidecars and source documents, and still had every one of the three sections come back `fail` on the first independent review — on real, evidence-grounded major findings, not nitpicks (a misattributed CCIC-ownership claim, a missing required risk-index caveat, an unsourced specific claim, and a fix that reproduced exactly the excluded sitemap detail it was meant to avoid at a "light" level).

One finding required two follow-up rounds: the first fix to 1.4 correctly removed the over-detailed sitemap labels but left an old table row that re-promoted the same excluded content under new packaging. A second independent check was needed to catch that the fix was only half-done.

**Pattern**: self-verification by the same agent that made the edit is structurally weak even when careful, because the agent's own mental model of "what I changed" doesn't include "what I forgot to also change." An independent reviewer with no stake in the fix and instructions to re-derive verdicts from source documents (not trust the drafting agent's summary) caught issues at a rate high enough that it should be treated as the expected outcome, not a surprise.

**How to apply**: when a task's own workflow calls for an independent editorial/review gate (as writing-th v5 does), budget for at least 2 fix-reverify cycles per unit as normal, not as a fallback path. Don't treat "I fixed the issue" as done until a genuinely independent check (fresh context, no shared rationale) confirms it — and re-verify with fresh eyes again after every fix, since a partial fix can look complete from inside the fixing agent's own frame.
