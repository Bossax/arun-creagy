# When a user's correction changes the shape of a plan (not just its size or detai

When a user's correction changes the shape of a plan (not just its size or detail level), salvaged content from the earlier wrong-shaped version needs re-derivation, not relabeling — keeping it under a new heading is itself a mistake even if the content is individually accurate. Before drafting a plan for an open-ended multi-session programme, ask what altitude it should sit at (spine/storyline vs. implementation-ready detail) rather than inferring it and presenting a complete artifact for correction. And when offering a multi-choice question about where to start (e.g. "which chapter/unit first"), include the user's likely unstated default (e.g. sequential order) as an explicit option, not just the assistant's own risk-based recommendation — otherwise the real preference surfaces only as a correction rather than a click. Secondary finding: bash's `find -printf`/`wc -l` silently truncate or drop long multibyte (Thai) filenames; PowerShell Test-Path/Get-ChildItem is the reliable verification tool for such paths.
