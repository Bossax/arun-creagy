# Learning: CRDB 5.3 sections draft best when service logic is preserved end-to-end

## Context

While drafting CRDB Sections 5.3.3, 5.3.8, and 5.3.9, the most reliable structure was not to treat each section as an isolated chapter objective. The stronger approach was to preserve one continuous logic chain from stakeholder interviews to workshop synthesis, from synthesis to prioritized services, from prioritized services to readiness and gap analysis, and from gaps to recommendations connected to governance and implementation.

## Pattern

For interconnected policy-report sections, draft quality improves when the writing process preserves the operational ancestry of the argument. In practice this means:

1. identify the evidence source clusters,
2. synthesize a shared note that explains how those clusters connect,
3. assign each section a distinct job in the chain,
4. write section prose so later sections inherit and extend earlier conclusions rather than repeating them.

## Why it matters

If this chain is not preserved, analytical sections drift into repetitive summaries or generic recommendations. When the chain is preserved, the recommendation section can legitimately claim that institutional, technical, and governance proposals arise from documented user demand and dataset constraints rather than from consultant-style abstraction.

## Practical rule

When drafting multiple linked report sections, define the service logic once and reuse it across sections as a cumulative spine:

- consultation evidence -> demand synthesis
- demand synthesis -> prioritized services
- prioritized services -> readiness/gap analysis
- readiness/gap analysis -> policy and technical recommendations

## Caution

Even if the substantive drafting is complete, the execution ledger can still become misleading if reminder status is not updated immediately. Artifact completion and process-state completion must be synchronized in the same session.
