## What happened

While drafting guiding questions for a 4-speaker CRDB dissemination panel, the user gave two corrections that each initially fixed only the flagged instance, requiring a second round of the same feedback:

1. "Don't force speakers to commit on the spot, don't make them look bad" — applied to the primary questions, but a *backup* question for the same speaker (asking DDPM to name what data it's "ready to share today," and whether DDPM would accept a hypothetical MOU) still violated the rule, because backups weren't re-checked.
2. "Isn't stating T-PLAT is a failure out loud rude?" — the main question about T-PLAT had already been softened in an earlier round, but a *backup* question ("so this platform doesn't repeat T-PLAT's fate") still implied his prior work failed, because only the main question was checked, not its backup.

## The generalizable lesson

A correction stated as a rule is a spec, not a patch. When applying it, grep/re-read the *entire* relevant document for every place the same pattern could recur (mains, secondaries, follow-ups, backups, other speakers/sections) in the same editing pass — don't fix only the cited line and move on. This is cheap to do immediately and expensive to skip, because skipping it reliably costs a second, sharper round of the same feedback.

## Secondary lesson: cultural/tone register for government panel content

For Thai government multi-stakeholder dissemination events specifically: never ask a speaker to commit their agency to a position on the spot (MOU acceptance, formal readiness statements), and never frame a question as if a speaker's own past work or agency failed, even in service of "sharp" or "direct" question design. This register reads as normal journalistic edge in some contexts but as genuinely disrespectful here. Treat it as a standing constraint for any future DCCE/CRDB panel or interview content, applied by default rather than only after correction.
