# Lesson: a DFR source's account of its own methodology is a claim, not a fact

When a draft-final-report source document describes how *it* was produced — "collection was carried out through 44 owning agencies using a standard form," "the option list was derived by reviewing platforms A/B/C" — that description needs the same source-fidelity scrutiny as any other claim in the document, not less. It is tempting to treat a document's self-description of its own process as more trustworthy than its substantive claims, but it isn't: it's still just text the document asserts about itself.

In the CRDB full-report §3.4 session (2026-09-01/02), an argument map built directly from `5.3.4`/`5.3.5` carried forward two such self-descriptions verbatim — a claim that data collection ran through 44 agencies via a standard form, and a claim that the product inventory's classification lists were derived from reviewing three named foreign platforms. Boss confirmed both were false: no agency interaction on verification ever happened, and the foreign platforms have no connection to this section's work at all. Both had been treated as safe to reuse because the DFR document stated them, despite this same document set having *already* produced one other verified error that session (a citation to a source file, `5.3.11`, that doesn't exist).

**Why this matters**: once a source is known to contain one factual error, that should raise — not lower — the bar for accepting its other unverified claims at face value, especially process claims that cannot be cross-checked against a data file the way a count or percentage can.

**How to apply**: when an argument-map unit's grounds rest on a source document's account of its own methodology, and that claim cannot be independently verified against a different artifact (a data file, a person's confirmation), flag it explicitly for human sign-off before treating it as settled — don't let "the source document says so" stand in as verification.
