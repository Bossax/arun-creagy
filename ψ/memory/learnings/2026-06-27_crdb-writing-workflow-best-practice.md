# Learning — CRDB writing workflow works best when feedback upgrades the style pack

## Pattern

For Thai technical report work, the most reliable workflow is not simple draft-and-revise. It is a five-part loop:

1. retrieve source evidence first
2. define the section job before writing
3. draft in Thai institutional prose
4. compare against the human-edited local voice, not only against abstract style rules
5. convert repeated wording failures into permanent style-pack guardrails

## Why it worked

This session showed that many writing errors were not factual errors. They were structural language errors: translated composite nouns, English sentence scaffolding, repeated section-function drift, and overly abstract architecture prose. Those errors kept recurring until the workflow itself changed. Once the style pack was upgraded with hierarchical vetting and sentence-shape bans, the writing process became more stable.

## Practical rule

When a human repeatedly corrects the same kind of phrasing, do not treat that only as a local edit. Promote it into the active style pack immediately. This turns revision friction into future prevention.

## Concrete signals to detect early

- paragraphs that sound like software specifications rather than Thai report prose
- overbuilt noun clusters such as translated architecture language
- openings built on negated pseudo-contrast such as `ไม่ได้...แต่...`
- repeated re-explanation of a concept already handled in a previous section

## Reusable method

For long Thai institutional writing, use this sequence as default:

- evidence retrieval
- section-boundary statement
- first draft
- NCAIF hierarchical vetting
- human comparison against edited local prose
- style-pack update if the same pattern fails twice
