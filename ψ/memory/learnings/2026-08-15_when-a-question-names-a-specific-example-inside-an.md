# When a question names a specific example inside an abstract/philosophical framin

When a question names a specific example inside an abstract/philosophical framing ("does X need Y — like this Z"), check whether the named example is real in the project's own corpus before reasoning about it abstractly. Abstract reasoning can be sound and still answer the wrong question if the "hypothetical" turns out to be a real, uninspected artifact. In one session, "does a dashboard need a business narrative, e.g. a Thailand climatology dashboard" was answered abstractly for two turns (including one wrong assumption) before a direct check revealed the dashboard was DEL-1, a real, unjustified DRD deliverable — the actual finding worth having. If the existence check is cheap (a grep), do it before answering in general terms, not after being asked to.
