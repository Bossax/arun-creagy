# When a user correction states a rule (e.g. \"don't force on-the-spot commitments,

When a user correction states a rule (e.g. "don't force on-the-spot commitments," "don't imply a speaker's past work failed"), treat it as a full-document audit requirement — re-check every variant (main questions, secondary questions, follow-ups, backups, across all sections) for the same violation in the same pass, not just the single instance that was flagged. Fixing only the cited line reliably costs a second, sharper round of the same feedback.

Secondary lesson: for Thai government multi-stakeholder panel/dissemination content specifically — never ask a speaker to commit their agency to a position on the spot (MOU acceptance, formal readiness statements), and never frame a question as if a speaker's own past work or agency failed, even in service of "sharp" question design. Treat as a standing constraint applied by default, not only after correction.
