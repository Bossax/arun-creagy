# writing-th verification discipline and the two-taxonomy plan trap: A CRDB writin

writing-th verification discipline and the two-taxonomy plan trap: A CRDB writing-plan document contained two independently-numbered Chapter 4 plans (Full Report vs. Executive Summary) with different section-to-topic mappings; a prior run drafted every Executive Summary section against the Full Report's plan sections instead, producing prose answering the wrong brief by one slot throughout. Separately, across one audit-and-rerun session, the same verification-skipping pattern recurred three times: reporting stages as "sound" without reading the drafts, citing a specific figure ("47 of 75") from an existing artifact without checking it against its named source (it didn't exist), and reaching for a generically-named but wrong tool (oracle_search, a cross-session learnings search) instead of following a skill's own explicit tool guidance when the answer was in a specific project folder. Practical rule: when a skill or plan document could plausibly be read two ways, do the check before presenting a conclusion, not after being asked to defend it. Apply by: (1) at Stage 0 of any writing-th run, explicitly confirm and record which section/taxonomy of a multi-taxonomy plan a contract is drawn from; (2) treat any specific number carried forward from an existing artifact as unverified until checked against its named source file directly; (3) when a skill names a specific tool for a specific purpose, use exactly that tool before reaching for a broader alternative that merely sounds related.
