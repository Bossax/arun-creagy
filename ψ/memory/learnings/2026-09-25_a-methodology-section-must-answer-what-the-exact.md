# A methodology section must answer WHAT (the exact question, from the TOR wording

A methodology section must answer WHAT (the exact question, from the TOR wording), WHY (why each step is necessary, with a concrete example), and HOW (written decision rules per step, the inputs and fields used, and the count at each step as a funnel). Failure case: CRDB §5.1 (2026-09-25) listed four abstract steps with no rules or numbers. The root cause was that Phase A never recorded its classification rules (tags were "the analyst's best guess"), and the writing pipeline turned the missing logic into fluent, empty prose. No gate (lint, editorial rubric, cold reader) checks whether a method is actually explained. The same section also coined a wrong label ("องค์ประกอบความเสี่ยง") for TOR 5.3.5's 8 information categories, assumed the catalog used those 8 (it uses 4 domains and 10 sub-domains), and let a catch-all "Response" tag hide system and governance requests. Before verbalizing any method section, confirm that a written method reference with explicit decision rules exists; if not, write it first. Verify taxonomy claims against the source files, never against earlier drafts. Fix reference: ψ/incubate/drafts/crdb-full-report-5.1/methodology.md.
