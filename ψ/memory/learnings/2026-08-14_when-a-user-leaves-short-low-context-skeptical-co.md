# When a user leaves short, low-context skeptical comments on a document produced

When a user leaves short, low-context skeptical comments on a document produced by an earlier thorough-seeming automated pass (e.g. "isn't X the source?", "doesn't Y cover this?"), treat it as a strong prior that something real was missed, not a misunderstanding to be politely corrected. Verify directly against primary source files rather than reasoning from memory of what was already checked. In one session every such comment (8+ instances across two documents) turned out to be a real, confirmable miss once actually investigated.

Once this pattern repeats 3+ times in a session, proactively scope a systematic re-check of the rest of the document for the same blind spot, rather than continuing to treat each new comment as an isolated one-off — repeated confirmation is itself evidence to act on.

Corollary: when a fix "rehabilitates" a previously-labeled gap by citing an asset that does exist, carry that asset's own documented limitations (access restrictions, unverified status, irreversible/lossy computation, etc.) forward into the new citation verbatim. Don't present the fix as a clean "gap closed" if the underlying asset still has real, undocumented-in-the-new-citation caveats — that reintroduces the same overstated-certainty failure mode in the opposite direction.
