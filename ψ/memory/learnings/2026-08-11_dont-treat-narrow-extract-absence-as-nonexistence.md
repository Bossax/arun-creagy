# 2026-08-11_dont-treat-narrow-extract-absence-as-nonexistence

**Context**: While cross-checking CRDB WP4's sitemap content requirements against DCCE's separate, narrower 260-row WP2 dataset catalog (`data_catalog_v4.csv`), one requirement's cited asset (a national M&E tracker dataset, ID `DAT-014`) wasn't found in that 260-row file. That absence was treated as evidence the asset didn't exist, and the page's coverage rating was downgraded from Full to Partial. It was wrong: `DAT-014` is a real, live, currently-maintained dataset on DCCE's own Data Governance Framework portal (`dgf.dcce.go.th/dataset/m-and-e`), maintained by a dedicated M&E evaluation team, tied to Thailand's official UNFCCC Biennial Transparency Report. The 260-row file is a curated subset built for a different work package (WP2), not DCCE's complete inventory — it simply hadn't captured this asset. The downgrade was reverted after checking directly against DCCE's live system, on the user's prompt (`/trace`) rather than by catching it independently.

**What worked**: Once told to trace the M&E platform claim, going straight to the source file that actually contained the asset in question (`DCCE_Unified_Digital_Asset_Database.csv`, the 391-item inventory `DAT-014` was originally cited from) rather than re-running the same narrower check resolved it in minutes — the URL field alone (`dgf.dcce.go.th/dataset/m-and-e`) was sufficient proof of a real, current, DCCE-maintained asset.

**Why**: A cross-check that treats "not found in file X" as "does not exist" is only as reliable as file X's completeness. When a check depends on a curated extract or subset (built for a narrower purpose, by a different work stream, on a different date), a miss in that extract is a weaker signal than a miss against the actual, broader source of truth — and should be flagged as "unverified against this narrower instrument" rather than promoted straight to a negative finding. This matters most exactly where a check is being run most rigorously, because that's precisely when a false negative does the most damage to trust in the result.

**How to apply**: Before treating an absence from any secondary/derived/curated data source as a real finding (a gap, a downgrade, "this doesn't exist"), check whether that source claims to be complete or is known to be a subset/extract. If it's a subset, either (a) verify directly against the broader/primary source before concluding absence, or (b) if that's not feasible in the moment, state the finding as "not found in [narrow source]" rather than "does not exist" — leave the stronger claim for after the primary-source check.
