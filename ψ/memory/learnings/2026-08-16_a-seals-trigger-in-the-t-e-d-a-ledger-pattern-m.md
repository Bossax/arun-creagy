# A seal's Trigger (in the T-E-D-A ledger pattern) must trace to the deliverable's

A seal's Trigger (in the T-E-D-A ledger pattern) must trace to the deliverable's originating mandate — the sprint plan, TOR clause, or governing decision doc that created the obligation for the deliverable to exist — never to the most recent session or review that happened to touch it. "What caused this text to change today" and "why does this deliverable exist" are different questions; only the second is a Trigger. Before proposing a T-E-D-A chain, check the deliverable's source-of-truth plan for an existing row/clause naming its scope — it's usually already written down. Reserve "this session's changes" for the Decision entry. Also default to one seal per deliverable rather than batching multiple work packages into a single chain unless explicitly told to combine them.
