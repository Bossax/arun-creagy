# Lesson: check for a real reference implementation before building CSS from a style-preset summary

**Context**: Building a Creagy-branded HTML slidedoc (`frontend-slides` skill) from the "Creagy Corporate" preset documented in `STYLE_PRESETS.md`. The preset entry is a compact prose summary (colors, font names, a short list of "signature elements"). I built the entire first version of the deck's CSS/HTML structure by inferring layout details from that summary plus a `python-pptx` inspection of a reference PowerPoint. Partway through a later correction pass, the user re-pasted `STYLE_PRESETS.md` and it had grown a `Visual reference` line pointing to `creagy_template_example.html` — a full, real, working HTML template the user had built separately (via their own `build_presentation.py` + PPTX extraction pipeline) that already encoded the exact class names, spacing, and structure I had been guessing at.

**What happened**: My guessed structure diverged from the real one in concrete ways — I invented my own class names (`.slide-header`, `.logo-badge`, `.kicker`) instead of the reference's actual system (`.header-left-box`, `.header-main-title`, `.header-sub-title`, `.header-logos`, `.doc-card`, `.slide-number-badge`, `.timeline-step`). I also violated an explicit preset rule ("NO top category tag lines") by adding my own kicker chips, which I would have avoided had I read the reference first.

**Why**: A prose-summary preset is lossy compared to a real file. When a preset both describes a style AND points (or later comes to point) at an actual template file, the file is the authoritative source — the prose is a human-readable index into it, not a substitute for it.

**How to apply**: Before building any CSS/HTML from a named style preset, check whether the preset references a real template/example file (in `STYLE_PRESETS.md`, a bold-template-pack `design.md`, or anywhere else the user might have pointed). If one exists, read it first — even if it requires working around large embedded assets (e.g. base64 images blowing a Read tool's token cap; use targeted `awk`/`grep` truncation instead of skipping the file). Only fall back to inferring structure from a prose description or an external source (like a PPTX) when no real reference implementation exists.

**Related**: [[wp9-slidedoc-visual-verification-gap]], general pattern also applies to any "style guide says X" situation — prefer the artifact over the summary.
