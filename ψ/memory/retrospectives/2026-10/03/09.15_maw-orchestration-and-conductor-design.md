## Lessons Learned

1. **Oracle Boundary Invariance**: An oracle's private memory and tools (`bureaucrazy.sqlite`, raw vector chunks) must remain encapsulated behind that oracle's sovereign boundary. The Conductor orchestrates by dispatching bounded questions and receiving structured briefs (`maw hey`), never by rummaging through a specialist's raw database.
2. **Event-Driven OS Waiters vs. LLM Polling Loops**: Multi-oracle synchronization does not require expensive 24/7 background daemons or continuous LLM polling turns. A non-blocking background OS process monitoring disk arrivals wakes the agent cleanly via Antigravity notifications at zero token cost.
3. **The Dual-Deposit Mandate**: For an oracle to be a genuine "Permanent Knowledge Vault", it must cache every synthesized brief into its own `ψ/memory/knowledge/` vault at the same time it deposits the deliverable into the requester's inbox. This transforms one-off answers into durable assets that resolve future repeat queries in 3 seconds.
4. **YAGNI in Multi-Agent Swarms**: Standing team charters (`maw team up`) carry heavy operational baggage: resident tmux panes, context window degradation, continuous token polling, and zombie processes. For discrete research inquiries, ad-hoc file-join convergence (Tier 3) is far faster, cleaner, and cheaper.
