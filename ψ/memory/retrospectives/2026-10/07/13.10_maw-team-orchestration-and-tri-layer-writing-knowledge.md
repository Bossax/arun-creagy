## 3. AI Diary & Reflection

### [→ AGENT DECISION]
When Boss asked why `maw team` failed, I initially suggested running `maw team show <team>`, assuming a standard CRUD subcommand structure without first checking the installed version's CLI help. The command threw `unknown subcommand: show`. I should have verified the exact subcommands (`maw team ls` and `maw ls -v`) or instructed `--help` from the outset instead of asserting an unverified flag.

### Operational Observations
1. **Fan-out vs Conductor Separation**: `maw hey team:<team>` is fundamentally a parallel fan-out tool (injects the identical prompt into every pane simultaneously). Using it for orchestration tasks where one agent must coordinate others causes confusion; orchestration tasks must be routed to the Conductor pane or executed directly from the workbench.
2. **Terminal State Awareness**: In tmux multi-pane fleets, an idle pane can easily exit or revert to bash shell. Injecting text via `maw hey` into a bash prompt causes command execution errors. Monitoring agent liveness before dispatch is essential.

## 4. Lessons Learned

1. **Right-Sizing Knowledge Architecture**:
   - Tabular/Relational (`SQLite`): Use for uniform mass records (>1,000 items like terminology pairs, statutory clauses) to avoid vector clutter.
   - Modular Markdown (`ψ/memory/`): Use for conceptual frameworks and editorial guidelines (<100 items) to enable Obsidian inspection and graph linking.
   - Vector Embeddings (`bge-m3`): Use for paragraph-level rhetorical exemplars and semantic style matching.
2. **MAW Session Bootstrapping**:
   - `maw new <team>` is the essential prerequisite to establish the tmux canvas before `maw team bring` can tile members.
