## AI Diary

The decisive moment was recognizing that these documents were not merely extra evidence for the warning-message research. They changed the object being studied. The article asks why information does not activate protection; the law proposal asks how the state could assign duties, finance action, and learn from failure. Keeping them inside the risk-communication folder would have made communication appear responsible for institutional problems it cannot solve.

[→ AGENT DECISION] I initially proposed `forecast-to-protection-research`, a coined label that sounded neat but obscured the actual scope. Boss rejected it as gimmicky. The better decision was to reuse Boss’s own direct formulation—`disaster-forecast-warning-preparedness-response`—because a research folder should tell future readers what it contains without requiring them to learn a new concept first.

The most useful analytical choice was to keep atoms inside two source summaries with stable IDs rather than create one file per claim. This preserved source provenance while allowing the synthesis and question briefs to reference exact knowledge pieces. The less polished part of execution was shell verification: two PowerShell commands contained an invalid empty pipeline and had to be rerun. They failed before mutation, but the repeated syntax mistake was avoidable; simple intermediate arrays were more reliable.

## Lessons Learned

1. When new evidence changes the unit of analysis, open a separate research domain instead of stretching an existing taxonomy until it loses meaning.
2. Use the human’s direct vocabulary for folder and project names; reserve new conceptual labels for findings that have earned them.
3. Atomic knowledge does not require one file per atom. Stable IDs inside source-faithful registers provide granularity with far less file overhead.
4. Separate four things explicitly: what a source asserts, what evidence it supplies, what the analyst infers, and what still requires research.
5. A cross-source synthesis is strongest when it records relationship types—such as `depends on`, `operationalizes`, and `creates tension with`—rather than merely combining summaries.
6. Hidden assumptions should become research questions with evidence and completion criteria, not caveat paragraphs that no one later resolves.
7. Scope Git staging to the approved folder in a dirty shared worktree and verify the cached path list immediately afterward.
