## Honest Feedback

Three friction points, unvarnished. First: I treated file discovery as solved the moment I found a plausibly-named match, when this repo's own documentation (AGENTS.md, the redirect-plan note) explicitly warns that content moves between drafting generations. A brief "let me confirm this is the live copy" step, cheap to do, would have caught this before any real work happened — the cost of skipping it was a full research-and-writing cycle done twice. Second: I inferred a citation convention from sibling files in the same folder as my target, rather than looking for an explicit style-rules document governing that folder's *programme*. The style document existed (`01-ข้อกำหนดรูปแบบการเขียนรายงานฉบับสมบูรณ์.md`) and directly contradicted what I'd inferred — I only found it on the second pass, prompted by the correction, not proactively. Third: recovery was fast once Boss flagged the error, but it required a second full plan-mode round trip and two more Explore agents — a real cost in time and context, even though the underlying research was reusable. The lesson isn't "be more careful" in the abstract; it's a concrete checklist item — before deep-diving a file, check for (a) a sibling drafting location with more recent commits, and (b) a scope/style-rules doc specific to wherever that file lives — before trusting a plausible match.

## Lessons Learned

- **Before deep work on a "found" file, verify it's the live one**: check git log recency, look for a parallel drafting folder (grep for the section's distinctive title text across the repo, not just under the folder you found it in), and read any project-level doc that warns about restructuring/supersession (this project's AGENTS.md does).
- **Citation/style conventions are scoped to the drafting programme, not just the folder**: a sibling file's convention is a hint, not a rule — look for an explicit format-requirements document before committing to a citation style, especially across a folder boundary (old `output/draft_final_report/` vs. new `ψ/incubate/drafts/crdb-full-report-*`).
- **When reverting a wrong-target edit, verify with `git status` before redoing work** — confirmed zero net diff on the old folder before touching the real file, which made the recovery auditable.
