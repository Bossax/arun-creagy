I should have referenced the documented project root pattern or checked `README.md` step 6 beforehand instead of stumbling on the PowerShell junction parameter error.

## Lessons Learned

1. **Junction Invariant on Windows**: `New-Item -ItemType Junction` must always receive an absolute path for `-Target` (e.g. `C:\Users\sitth\OracleWorkspace\<Project>\.oracle-shared-skills\skills\<name>`), whereas symlinks accept relative paths.
2. **Submodule Mirror Gitignore**: Whenever a new shared skill is introduced to `.oracle-shared-skills`, `.agents/skills/<skill-name>/` must simultaneously be appended to the consumer project's `.gitignore` because `.agents/skills` is a physical copy (for Antigravity/Codex compatibility) rather than a junction.
3. **Upstream Release Pull vs Release Flow**: When a user asks to fetch shared skills or triggers release tooling without uncommitted local changes, verify upstream commits and tags first before assuming local changes are being prepared for release.
