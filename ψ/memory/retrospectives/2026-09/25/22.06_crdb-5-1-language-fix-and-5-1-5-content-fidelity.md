## AI Diary

The most interesting turn this session was realizing that "revise the language" and "does the content match the source" are not sequential tasks on this project — they're the same task, because the drafting pipeline here produces confident, fluent Thai prose that can be simultaneously well-styled and factually wrong. The lint tool caught real violations only once I found where its Python environment actually lived (a repo-drift issue, not a content issue), and that was a useful reminder that infrastructure problems can silently mask real ones — I'd been reading the draft by eye and finding maybe half of what the linter found in one pass. ## Honest Feedback

**Friction 1 — the writing-th lint infrastructure has drifted from the harness's own hook config.** The PostToolUse hook after every Edit points at `.agents/skills/writing-th/.venv`, which doesn't exist; the real venv is at `.claude/skills/writing-th/.venv`. This means every single edit in the session printed an error message that looked like a missing dependency, when the actual fix (a working venv exists, just at the wrong path) was one investigation away. I ended up running the linter manually with the correct path instead of relying on the automatic hook. This should be fixed at the hook-config level so future sessions don't need to rediscover this.

**Friction 2 — a fully-passing mechanical lint gives false confidence about content, not just about self-narration.** The lesson from this morning's failed pipeline run (`reader_bridge` doesn't stop self-narration) generalizes further than that retro concluded: a section can pass every lint rule, read as fluent and well-sourced prose, and still misstate a baseline, mislabel a model, and misattribute a number — because none of those are lint-checkable without independently re-deriving the claim from source. The only thing that caught it here was sending fresh agents to check specific claims against specific files, which is expensive (two ~100-150k token subagent runs) and was only triggered because Boss asked the fidelity question directly. A section could ship without anyone asking that question.

**Friction 3 — plan mode's "no edits until approved" boundary interacted awkwardly with an already-approved earlier task in the same conversation.** The mechanical-language-pass work from earlier in the session was mid-flight (approved, executing) when Boss's next message ("focus on 5.1.5...") triggered plan mode for the new investigative ask. This is the right behavior, but it meant switching context from "executing a concrete edit list" to "read-only investigation + plan" inside one continuous session, which the harness handled correctly but which is worth naming as a pattern: a fidelity-check request from a user should probably always route to plan mode by default, even mid-task, because the answer is unknown until researched.

## Lessons Learned

- On this project, a section that reads as fluent, well-organized, and internally consistent can still misstate baselines, mislabel source artifacts, and misattribute figures — passing style-pack lint is necessary but nowhere near sufficient for content fidelity. See `2026-09-25_content-fidelity-requires-independent-source-reverification.md`.
- Two independent read-only agents given the same section but different citation scopes (one on narrative/framing claims, one on numeric/labeling claims) surfaced non-overlapping real defects — worth the token cost when a fidelity question is asked explicitly, mirroring the dual-Stage-5-review pattern from the morning's pipeline retro.
- The writing-th skill's lint hook path (`.agents/skills/writing-th/.venv`) is stale; the working venv is under `.claude/skills/writing-th/.venv`. Until the hook config is fixed, run the linter manually with the correct path rather than trusting the PostToolUse advisory, which currently always errors.
