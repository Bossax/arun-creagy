## Honest Feedback

Three friction points. First, I should have run every direct quote and borrowed phrase from source material through the lexicon mentally before writing it into new composed prose, not just checked qwen's output — the "ห่วงโซ่" catch worked because the lint hook exists, not because I anticipated it, and I'd already had the exact lesson about rule application blind spots one session earlier. Second, the org-count investigation took several tool calls (evidence table, evidence-traceability file, an archived v2 matrix, a trace file) before landing on a clean answer, and I could have led with the primary evidence table first instead of reading the trace file and v2 matrix, which turned out not to resolve anything — a more efficient search order would have gotten to the same confirmed answer in fewer steps. Third, I still don't have a lighter-weight way to diff-check a merge like this beyond full manual reading; it worked at 8-9 paragraphs, but I noticed myself relying on remembering what I'd just read rather than a structured comparison, which is a fragile process to scale to a busier chapter section.

## Lessons Learned

- **A phrase lifted verbatim from source material into new composed prose is not automatically safe just because it existed in the original.** Lexicon and pattern bans apply regardless of provenance — check borrowed phrasing against the current rule set before writing it, the same way qwen's output gets checked, rather than assuming "it's in the source" is a pass.
- **When a stakeholder gives a factual correction that conflicts with a primary, dated, appendix-anchored evidence artifact, present the artifact rather than silently complying or silently overriding.** This isn't about not trusting Boss — it's that a specific number tied to specific evidence (interview dates, appendix anchors) is stronger than a recollection, and the right move is to make the conflict visible so the person with authority over the fact can resolve it with full information, which is exactly what happened here.
- **When a P-classified topic's registry lists two source columns, don't assume they're the same content at different granularity — read both before proposing a plan.** §3.1 had a single clean source; §3.2's two sources covered genuinely different material, and that difference wasn't visible from the registry table alone.
