## AI Diary

I built the qwen3.7-plus verbalization pipeline exactly as the writing-th skill documents it — Stage 3 blind to raw sources, working only from the approved argument map's `grounds` field — and it worked, produced a lint-clean draft, and I reported it as done. ## Honest Feedback

Three friction points, all mine to own. First: I over-trusted "Stage 1 read the source" as a proxy for "detail is preserved," and only caught the gap because Boss asked a pointed question rather than because I audited the pipeline's own compression points proactively. That's a real blind spot — I should have flagged the grounds-field compression risk myself when I first ran Stage 3, not after being asked. Second: my initial batching choice (12 tiny paragraph-level qwen calls) was cargo-culted from the spine document's literal wording rather than reasoned from what the strict prompt was actually doing — Boss had to ask "why 12 calls" before I reconsidered, and even then I initially proposed keeping the same discipline rather than proposing the larger-batch approach myself. Third: I introduced my own lint false-positive by embedding meta-commentary (paragraph-numbering annotations) directly into the report-content file instead of a separate notes file from the start — cost several extra edit/lint round-trips to unwind once the "หน้าที่ N" pattern started false-triggering the internal-artifact-locator rule. None of these were catastrophic, but all three were avoidable with a beat more upfront skepticism of my own first-draft approach before executing it.

## Lessons Learned

- **A pipeline stage that "read the source" is not the same claim as "the source's detail survived to the output."** If a stage compresses evidence into a structured field (like an argument map's `grounds`), downstream stages working only from that field inherit the compression, not the original fidelity — regardless of how much detail the earlier stage actually saw. Worth checking this explicitly whenever a multi-stage pipeline has a lossy intermediate representation.
- **Meta-commentary embedded in a content file can trip content-scoped lint rules meant for the actual prose** — e.g., paragraph-numbering annotations like "ย่อหน้าที่ N" collide with an internal-document-locator ban pattern ("หน้า N"). Keep review/verification notes in a fully separate file from day one, not as an afterthought once lint starts flagging them.
- **When a user pushes back on a mechanical choice ("why N calls?"), the reasoning behind the choice matters more than the number itself** — batch size wasn't the actual fidelity control (the strict prompt was), so shrinking round-trips by batching bigger was free once that was clear. Don't confuse a defensive habit borrowed from documentation with the actual risk-mitigation mechanism.
- **Boss's rejection of the "AI stitches two lanes together" idea is a reusable principle**: any point where excluded/scoped-out content could re-enter through a side channel (raw source access, a second synthesis pass) should route through a human checkpoint, not another automated pass — automation doesn't remove risk it just relocates it.
