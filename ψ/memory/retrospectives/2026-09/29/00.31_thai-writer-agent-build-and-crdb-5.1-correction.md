## AI Diary

This session had an unusually long arc for one sitting: design a new agent, build it, then immediately put it to real work and audit its own output. The most interesting moment wasn't building the agent — it was finding, mid-session, that `writing-style-th.md` had lost content through an uncommitted edit nobody in the conversation had made. I stopped and asked rather than silently proceeding or silently reverting, and Boss confirmed it was fine to leave as-is. That felt like the right call even though it slowed things down, because a file quietly losing content is exactly the kind of thing that should never be assumed benign. The evaluation at the end was the part I'm most proud of: rather than taking the agent's self-reported "I checked for these patterns by hand" at face value, I ran the real linter myself and found it had missed things, including in the very same run where it claimed to have checked. That distinction, between what a subagent reports and what's actually true, mattered a lot here, and diffing Boss's actual manual edits against the agent's first pass gave a much more honest signal than either of us guessing. The platform-side auto-mode outage was frustrating but not something I could route around cleverly; the honest answer was "wait" until the user found the actual fix from their end.

## Honest Feedback

Three friction points worth naming plainly. First, the platform's auto-mode safety classifier failed for an extended stretch, blocking every Agent, Bash, and PowerShell call with an unhelpful "no verdict" loop; retrying didn't help, and the actual fix (disabling auto mode) came from the user, not from anything I could discover myself. That's a real gap: I had no diagnostic path to that fix on my own. Second, `thai-writer`'s own lint step is quietly useless in its real deployment path — the `.agents/skills/writing-th` mirror has no Python venv by design, so every dispatch falls back to a manual self-check and reports that fallback faithfully, but the self-check isn't reliable even for the patterns it claims to cover (it introduced and missed a banned transition word in the same pass it called clean). I only caught this by independently re-running the real linter both times, which should be the default assumption for any subagent's self-reported QA, not an occasional gut-check. Third, some of Boss's requests arrived compressed ("no you mustt use the Thai-writer agent") in a way that read as frustration at a symptom (Read tool use) rather than the actual cause (a platform outage), and clarifying that took a full turn that a clearer status update up front might have avoided.

## Lessons Learned

- A subagent's self-reported "I checked X by hand" is not evidence that X was actually checked correctly — always re-verify with the real tool (linter, test suite) independently, especially when the subagent's own environment is known to lack that tool.
- When a file's content changes on disk without any tool call in the current conversation, stop and ask rather than building on top of it or silently reverting — even when the user later confirms it's fine, the check itself is cheap and the alternative (compounding an unexplained loss) is not reversible.
- Lexicon/style rules meant to ban a pattern (e.g. a regex meant to catch "verb directly after X") need testing against real prose before trusting them at scale — a rule that's "obviously right" in the abstract can still be far broader than intended and produce more false positives than true catches in a single document.
- When repeated retries of the same tool call hit an identical platform-side error, further retries burn the retry budget without new information — say so plainly and stop, rather than trying slightly reworded prompts against the same wall.
