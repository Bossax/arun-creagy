## Honest Feedback

Three friction points worth naming plainly. First, the qwen3.7-plus stall (24+ minutes, no output, on a prompt maybe 25% longer than the one that succeeded in under 2 minutes) cost real session time and had no diagnostic signal — I don't know if it was a token-limit issue, a rate limit, or something else, and neither the tool nor I could tell mid-flight. Second, `warrant_trace.py` was completely useless on this section — it compares English argument-map claim terms against Thai prose and reports every single unit as NOT FOUND regardless of actual fidelity, since the vocabulary never overlaps by design. I fell back to manual line-by-line comparison, which worked but is exactly the kind of check the script exists to automate. Third, I generated a 13-unit argument map with three factually wrong units before Boss caught them — the errors came from trusting DFR source text at face value (agency collection process, platform-derivation claim) rather than treating "documented in the source" and "actually happened" as separate questions requiring separate verification, especially for a document I already had one confirmed instance of being wrong (the 5.3.11 citation).

## Lessons Learned

- When a DFR source document describes its own methodology ("we collected via form X sent to Y agencies," "we derived Z from reviewing platforms A/B/C"), that description is not automatically true — it needs the same skepticism as any other claim, especially once one factual error has already surfaced in the same document set.
- `warrant_trace.py` cannot meaningfully check English-map-to-Thai-prose fidelity by term overlap; treat its output as always-fail noise for Thai verbalization and do the fidelity check by hand, unit by unit.
- When a coordinator claims a draft needs wholesale regeneration, re-verify that claim against the actual file before acting on it — the real defect was narrower and the fix was targeted edits, not a rewrite.
- A stalled MCP call with no output after several multiples of the normal duration is worth killing rather than continuing to wait — there's no partial-output signal to judge whether it's almost done.
