## Lessons Learned

- When a user says "make it global" mid-plan for an MCP server, that changes two things, not one: the registration scope (`claude mcp add -s user`) AND the script's file location — a global tool's source shouldn't live inside one specific project's directory tree, since that couples "works everywhere" to "this one repo still exists on disk."
- Never assume max_tokens defaults are generous enough for a multi-unit verbalization prompt on an unfamiliar provider; a first-time call to a new model should set an explicit, generous max_tokens rather than relying on provider defaults, since a silent truncation (no error, no finish_reason surfaced to the caller through this MCP tool) can look like a complete, coherent answer.
- An LLM asked to verbalize structured argument-map data into prose can silently substitute a plausible-sounding but wrong category (here: "private sector" for "domestic") even under explicit instructions not to alter given wording — this is a controlled-vocabulary-preservation failure mode worth testing for specifically, not just trusting instruction-following to prevent.
- Pulse data that goes stale (frozen since a single early session) should be explicitly flagged as unreliable rather than silently included in retros/recaps — a recurring `/rrr` and `/recap` friction point across sessions now.
