## 4. Lesson Learned Pattern
- **Pattern**: Never use destructive mirror synchronization into an existing Git-backed deployment repo unless the deletion set has been explicitly validated.
- **Concept**: `[git, deployment, filesystem-safety, verification, trust-recovery]`
- **Learn**: For app promotion from a development folder into a deployment repository, treat the deploy repo as the system of record. Restore the repo first if its Git metadata is damaged. Then use a one-way overlay copy that excludes `.git` and runtime artifacts, followed by a file-count and hash-based comparison between source and target before declaring the migration complete.
