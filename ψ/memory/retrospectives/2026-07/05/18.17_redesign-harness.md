## 3. Retrospective Analysis & Lessons Learned

### Friction & Pitfalls
*   **System Prompt Bloat**: Storing specialized task constraints (like style checks and writing formats) in global system prompts creates cognitive noise for non-writing tasks. It wastes token space, slows down execution, and creates contradictory instructions between "direct and concise" coding personas and "slow and methodical" writing personas.
*   **Soft Semantic Harnesses**: Relying on markdown guidelines to enforce AI behavior is highly vulnerable to "Goal-Completion Bias" under high context load. The model will bypass text-based rules to finish generation unless physically blocked.

### Correction & Strategy
*   **Task-Driven Harnessing**: Keep the global system prompt extremely lean (only directory structures and critical, non-negotiable MCP boundaries). Route specialized rules into localized skills.
*   **Hard Programmatic Gates**: Replace self-auditing markdown checklists with deterministic Python scripts (`lint_thai_writing.py` and `check_density.py`) running in the terminal. The model cannot bypass the check because it cannot fake an exit code `0`.
*   **Draft Isolation**: Formally segregate raw generation (`ψ/incubate/drafts/`) from production outputs (`ψ/writing/`).

### [→ AGENT DECISION]
The agent initially attempted to fix prompt-level safety failures by writing *more* system prompts (`02-identity.md` and `05-harness-discipline.md` upgrades) rather than reducing global bloat. The wrong choice was trying to cure prompt-overload with more prompts, instead of immediately shifting constraints to task-specific skills and deterministic scripts.
