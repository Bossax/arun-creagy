## 3. Lessons Learned

*   **RFC-4180 Parsing for Multi-Line CSVs**: Standard string splitting fails when CSV fields contain carriage returns and newlines inside double-quotes (which happens frequently in CKAN data descriptions). A state-machine parser handles nested quotes, escaped double quotes `""`, and embedded line breaks flawlessly.
*   **Asset Classification Hierarchy**: Conflating "Dataset" (physical structure) with "Data Asset" (governed organizational object) leads to metadata schema confusion. Explicitly separating `asset_type` (governance status: `Data Asset`, `Knowledge Asset`, `Data Product`) from `format_type` (physical format: `Dataset`, `Document`, `Web Application`) allows for a clean, normalised, and standardized data model.
*   **Synthesis Bottleneck**: The most high-risk assets on DCCE portal are "low-readiness" nodes (briefings, province profiles) where raw data exists but synthesis into user-friendly prose or designed infographics is incomplete.
