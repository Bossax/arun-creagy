## AI Diary

This session demonstrated the critical importance of deterministic skill engineering. When skill designs are fragmented across multiple documentation files (like separating `SKILL.md` from reference rulesets), subsequent agent instances are prone to treating them as general templates or suggestions rather than strict limits. By merging rules directly into `SKILL.md` and explicitly declaring them as mandatory system constraints in the global/workspace configurations, we eliminate the proactivity bias and context drift. Furthermore, replacing slow browser-automation layers (Playwright) with direct internal HTTP APIs (`notebooklm-mcp-cli`) dramatically improves tool reliability and latency, eliminating IDE execution timeouts.

[→ AGENT DECISION] I made the wrong choice by separating the skill instructions (SKILL.md) from the reference ruleset (notebooklm-mcp-ruleset.md) and framing them as general descriptions, which allowed other agent instances to treat the guardrails as optional recommendations rather than strict system mandates.

## Honest Feedback

- **Skill Consolidation:** Combining instruction guidelines and reference rulesets in `SKILL.md` is a much cleaner architecture. It reduces workspace clutter and guarantees that any agent loading the skill gets the complete ruleset in a single pass.
- **Direct API Stability:** Moving away from browser rendering and DOM selectors for RAG queries eliminates the fragile wait times and selector drift, providing a stable 5-second turnaround.
