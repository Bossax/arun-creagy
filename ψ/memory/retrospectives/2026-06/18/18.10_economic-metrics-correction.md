## Summary
Corrected a critical misconception regarding the economic metrics in the CRI Phase 1 dataset. The metric previously labeled as "Total Economic Loss" is actually the **Government Advance Payment** (emergency relief funds), which is denominated in **THB**. This contrast with the **Million THB** unit used for Gross Provincial Product (GPP) required a structural correction in the export pipeline and UI labels.

## What We Did
- [x] **Corrected Pipeline Logic**: Updated `tmp_stage1_export.py` to treat relief as THB and align it with Million THB GPP for ratio calculation.
- [x] **Regenerated Assets**: Rerun the Stage 1 export script to produce valid JSON artifacts.
- [x] **Documentation Sync**: Updated `pages/methodology.py` to reflect the relief-based proxy and accurate unit descriptions.
- [x] **UI Label Fix**: Synchronized `pages/cri.py` with the corrected metric names and units.

## [→ AGENT DECISION]
**Wrong Choice**: Assuming "Loss" and "GPP" were in the same scale (Million THB) based on previous pilot data, leading to a 1,000,000x error in the initial CRI calculation.
**Correction**: Verified the raw silver data source (`silver_govt_adv_payment_annual_long.csv`) to confirm THB scale and implemented explicit unit conversion in the pipeline.

## Blockers & Learnings
- **Unit Drift**: In government datasets, "Loss" can refer to actual damage (rarely tracked consistently) or government expenditure (relief). We must always check the specific budget code or source metadata.
- **Environment Pathing**: Virtual environments on Windows use `Scripts\python.exe` and must be accessed via absolute paths when working across symlinks like `ψ`.
