## Honest Feedback

**Friction point 1 — I found my own tallying error only because I re-verified before publishing, not because I got it right the first time.** When drafting the format-check batch for the node-level deep dives, I miscounted node 2.3's full/partial/gap split (wrote 5/3/2, actual was 4/2/5) and only caught it while re-deriving the numbers for the remaining 12 nodes. If the user hadn't asked for all 15 nodes — if the 3-node format check had been the final deliverable — that error would have shipped. Re-verification before publishing is good practice, but I should be doing arithmetic-heavy classification work with a script or table cross-check from the start, not eyeballing status counts across a long CSV read.

**Friction point 2 — I initially wrote the "close the analysis loop" section in a way that implied all 8 reclassified items had the same kind of uncertainty as the M&E item, and the user had to correct that distinction explicitly.** The M&E item was an existence question (missing from the extract entirely); the other 7 were a maturity question (present in the extract, but flagged Restricted/Draft). Collapsing those into "check them the same way" was imprecise, and I should have caught that distinction myself when writing the follow-up section, since I had the underlying subagent report showing the difference right there — I just didn't re-read it carefully enough before summarizing.

**Friction point 3 — the seal-chain construction took two rounds of correction from the user, which suggests I don't yet have the T-E-D-A discipline internalized as well as I should for a skill I've now used multiple times in this project.** Evidence-vs-asset conflation and getting the Trigger's altitude right (motive, not restated task) are both things the skill's own documentation states plainly. I should re-read the skill file itself before constructing a chain, not just pattern-match against the last sealed entry's shape.

## Lessons Learned

- **"Missing from a curated extract" and "doesn't exist" are different claims, and it's easy to silently collapse them while writing.** When a cross-check depends on absence-from-a-file as evidence of non-existence, the file's own scope/completeness needs to be verified before treating a miss as a finding — not assumed. (See `2026-08-11_dont-treat-narrow-extract-absence-as-nonexistence.md`)
- **In a T-E-D-A seal chain, Evidence and Assets must never be the same artifact** — Evidence is the raw discovered material that grounds a decision; Assets are the hardened, authored outputs the decision produces. Citing a deliverable as evidence for itself is circular and the user caught it immediately.
- **When re-scoping a report on request (dropping a section, changing tone), just do it cleanly rather than hedging** — the user narrowed the NCAIF report's scope twice in this session and both times a direct, confirmed edit to the plan file worked better than re-litigating whether the narrower scope was sufficient.
