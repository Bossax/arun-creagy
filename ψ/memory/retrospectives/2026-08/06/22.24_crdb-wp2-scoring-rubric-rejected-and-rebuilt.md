## AI Diary

When I first proposed the WP2 scoring rubric, I felt confident about it — five criteria, each grounded in an actual CSV column, felt like a defensible method. ## Honest Feedback

**Friction point 1 — I initially over-trusted convenient signal.** The five-criterion rubric felt legitimate because it had structure and used real columns from a real CSV. But structure isn't evidence. I should have asked myself "what would make this criterion wrong" before proposing it, not after being asked.

**Friction point 2 — the custom agent definition didn't work as planned.** I designed the pipeline around a `.claude/agents/wp2-demand-scorer.md` file with `reasoning_effort: high`, only to discover mid-execution that custom agent definitions don't hot-load within a running session. This should have been checked before finalizing the plan, not discovered at execution time — wasted a round-trip and a slightly awkward "actually, fallback" moment in front of Boss.

**Friction point 3 — I carried forward an unverified specific claim.** When first explaining the "3+2" list, I named the three existing tools ("spatial risk database, hazard/exposure map, Climate Risk Index") from memory of the plan file's phrasing without checking it against the actual source document. When asked to elaborate, I went and checked and couldn't confirm that specific naming anywhere in the briefing deck. I flagged this honestly rather than doubling down, which was the right call, but the better move would have been not asserting unverified specifics in the first place.

## Lessons Learned

- A scoring rubric built entirely from a single data source's own metadata is not evidence — it's the source re-describing itself. Independent grounding has to come from a different document/signal than the thing being scored.
- Check whether a custom subagent definition needs a session restart *before* designing a pipeline around it, not after launching the first stage.
- When citing a specific fact from memory (a document's exact wording, a named list), re-verify against source before stating it as settled, especially when the fact will inform a scoping or scoring decision downstream.
- Sequential narrow questions from a domain expert ("how do you know X specifically") are often a sign the whole approach needs re-grounding, not that each point needs a slightly better justification. Don't defend criterion-by-criterion; step back and ask what's actually missing.
