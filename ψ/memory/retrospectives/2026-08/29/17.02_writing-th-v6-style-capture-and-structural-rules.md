## 4. Lessons Learned

1. **Smart Diff Resolution is Mandatory for Style-Capture**: Style edits frequently exist in Git history (as committed work) or in sibling baseline files (`*.pre-*.md`). A single `git diff <file>` check is fragile. The 3-tier fallback ladder prevents commit blindness.
2. **Structural Rules Need Dedicated Typed Stores (Not Lexicons)**: Macro-level document architecture (4-question deliverable tables, framework enumeration lists, 4-layer system stacks) cannot be expressed as simple regex string swaps. Storing them in `STRUCTURAL_RULES_<CONTEXT>.json` and gating them via Stage 1 `th-argument-mapper` closes the loop between human structural edits and automated argument generation.
3. **Always Check the Project Inbox / Architecture Notes Before Inventing Solutions**: The repository's inbox notes already contained deep research on writing science and the L1–L5 layer breakdown. Grounding changes in pre-existing architecture analysis avoids reinventing flawed mechanisms.
