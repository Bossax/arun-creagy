## AI Diary

The thing I keep returning to is how much sharper the audit got the moment I stopped reading the code and started running it. I could have written a competent review of `writing-th` from the SKILL.md alone and it would have missed every real defect — the dead rules look fine as JSON, the infinite loop is invisible until you notice a replacement contains its own banned string, and the ungated merge reads as a deliberate design note in a comment.

I was corrected three times today and was wrong all three. The persona ordering — I had the evidence in hand, quoted the style pack's own activation map two turns earlier, and still drew a diagram with persona at stage zero. The register missing from the loop diagram, after I'd argued it was shared state both arcs touch. And the WP5 report, where I led with "22 of 24 violations were parentheticals" as if it were evidence, when it's an internal analysis artifact that was never in the gate's scope. That one bothers me most. I measured the wrong thing and presented the number confidently, which is exactly the over-claiming failure I'd spent the afternoon documenting in someone else's code.

The good version of today is that every fix is verifiable. The fixtures disagree with the old linter on eleven of twenty cases. That number is checkable by anyone, and it's the kind of claim I want to be making.

## Honest Feedback

**I led with a bad measurement.** The WP5 statistic shaped two turns of design discussion before Boss pointed out the document was out of scope. I should have asked what kind of document it was before treating its output as signal. The register now holds that run, so the one real data point in it is from a non-target file.

**Heredoc quoting cost real time.** Backslashes were being mangled between the shell and Python, which silently corrupted a regex into a literal newline and produced a syntax error I then had to chase. I burned three cycles before switching to writing patch scripts as files. I should have switched after the first failure, not the third.

**I misranked the register and half-ignored a stated constraint.** Putting the register in tranche 2 was wrong — it is a log, and delaying a log loses data in a way the other items don't. Separately, I proposed auto-invoking `style-capture` at the end of Stage 6 when the workflow had already been described as manual. Neither is a large error, but both are cases of me optimising for a tidy architecture over what was actually asked.

## Lessons Learned

- **Gate the producer, not only the consumer.** `style-capture` writes the lexicon that `lint_thai_writing.py` reads. The reader was gated and the writer was not, which is how three malformed rules reached production and sat there silently.
- **A rule that cannot be an exact string or a compiling pattern is not a lexicon entry.** Writing its English description into `banned` makes it a no-op that looks like enforcement.
- **Verify the target is in scope before reporting a measurement.** A number from the wrong document is worse than no number.
- **Name a gate for what it enforces.** Stage 5 claimed determinism over a tenth of the pack.
