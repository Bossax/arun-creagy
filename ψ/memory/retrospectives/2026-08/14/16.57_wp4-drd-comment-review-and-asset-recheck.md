## Architecture / Process Decisions

- **Verify before reflecting.** Every comment got checked against actual source files before I answered "here's my read" — this is what surfaced the missed A-BTR Section B and the DS-01 cross-reference gap. Guessing at what Boss meant would have missed both.
- **Descope vs. simplify are different operations.** When Boss said "this page just hosts what exists," I initially planned to just soften the storyboard's prose. Boss meant something stronger — walk back the actual requirement. I checked whether that would contradict deliberately-written DRD language first, found it would, and surfaced that conflict rather than either blindly complying or blindly refusing.
- **Caveats travel with citations.** When adding SYS-003/`DCCE_3_x` as a "confirmed" asset for REQ-008/014, the fix had to carry forward Appendix B2's existing Unverified-Baseline/irreversibility language, not present it as a clean win — Boss's mid-session question about data-backbone concentration made this explicit, but it was the right instinct even before that.
- **Concurrent-repo-state safety.** Discovering a commit I didn't make, mid-staging, was a stop-and-flag moment, not a "shrug and continue" one — matched it against the general instruction to investigate unfamiliar git state before acting further.

## Lessons Learned

- When a stated correction from the user implies a scope change (not just a wording change), check the affected artifact for *deliberate* prior language before applying the change — the artifact may already protect against the exact mistake the naive fix would introduce.
- A repeated pattern of "user comment turns out to be right" across 3+ instances is itself a signal worth acting on proactively (scope a systematic check) rather than continuing to handle each instance as a one-off.
- Mid-staging is a valid moment to notice and stop for unexpected git state — don't wait until after `git commit` to register that something's off.
- "Generous matching" (accepting narrative/adjacent content as real support) and "carry caveats forward" (not overselling a citation) are not in tension — both were live in the same session, applied to different situations, and conflating them would have caused either over-caution or over-claiming in the wrong spot.
