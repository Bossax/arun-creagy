## Architecture Decisions

- **Spine vs. intra-chapter design as a hard boundary.** After two corrections, the working rule is: the spine session states each chapter's governing question, argument, and key outputs, plus a magnitude note (P/P+/R mix, existing base size, argument-map coverage). It does not design subsections, paragraph jobs, or drafting-unit splits — those are decided live in that chapter's own session. This boundary exists because Boss explicitly separated report-level/inter-chapter ownership (his) from intra-chapter ownership (mine), and the first two plan drafts blurred it in opposite directions — first by jumping straight to chapter 5 subsection design, then by keeping that design after reframing as "spine."
- **`prior_draft` = exec draft, not the old clause file.** Chosen so Stage 1's revision mode recovers the *approved* argument rather than the old storyline; the `draft_final_report` clause file becomes a `source_path` supplying full-report-altitude detail instead.

This reshapes expected effort per chapter and is now recorded in the spine rather than left implicit.

## Lessons Learned

- When a user's correction changes the *shape* of a deliverable (not its size or detail level), check whether content salvaged from the earlier wrong-shaped version still belongs — relabeling it into the new structure without re-deriving it is itself a mistake, even when the content is individually accurate.
- Before drafting a plan in Plan Mode for an open-ended, multi-session programme, ask what altitude the plan should sit at (spine vs. implementation-ready) rather than inferring it and presenting a complete artifact for correction — especially when the task naturally decomposes across sessions.
- When offering the user a multi-select "which unit/chapter first" question, include the straightforward sequential-order option explicitly, not just the option the assistant's own risk-based reasoning favors — a user with an unstated default (start from the beginning, in order) may not think to type it as "Other" if it isn't visible as a natural choice.
- Bash's `find -printf` and `wc -l` silently truncate or drop long Thai (multibyte) filenames in this repo; PowerShell `Test-Path`/`Get-ChildItem` is the reliable tool for verifying Thai-named paths.
- Stale pulse data (`ψ/data/pulse/*.json`, last updated March 2026 for this project) has now surfaced identically in two different skill invocations — worth surfacing to Boss rather than continuing to silently skip it.
