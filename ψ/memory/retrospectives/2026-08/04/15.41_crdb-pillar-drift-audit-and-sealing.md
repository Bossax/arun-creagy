## Lessons Learned

1. **When proposing a T-E-D-A chain, read the originating document, not just its most recent successor.** The temptation is to cite the "final" artifact in a lineage because it's cleaner, but the ledger's whole purpose is preserving causality — the older document is often the one that actually explains *why*.
2. **A `/trace --deep` isn't done when the agents report back — it's done when the trace log is written and bonded via `oracle_trace`.** Compiling a nice chat summary from agent outputs is not the deliverable; it's an intermediate step. This is the second time in one session I nearly treated agent synthesis as the finish line (see also: the earlier TOR70 trace, which I did complete correctly) — worth checking explicitly against the skill's numbered steps before declaring done.
3. **When redesigning a skill's default methodology (e.g., splitting agents by topic instead of location), state the trade-off and get a nod before launching, not after.** The user is going to ask anyway if the deviation is real; asking first costs one turn and avoids the appearance of an unexplained methodology change.
