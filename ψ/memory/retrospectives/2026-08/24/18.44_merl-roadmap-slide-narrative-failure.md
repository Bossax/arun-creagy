## Analytical gains

The most valuable result is the distinction between the roadmap's capability model and DCCE's current operating capacity.

The Boss's proposal contains six necessary functions: governance; results framework; data handling; quality review; evaluation and research; and learning and use. The synthesis work showed that the main constraint is not the absence of these concepts. The constraint is whether information can move repeatedly through Thai line agencies, DCCE, evaluation, learning, and an authorized decision.

The fixed project must therefore be understood as three nested layers:

1. Six-sector coverage required by the TOR.
2. One-sector deep operational test using approximately 10–15 existing indicators.
3. A system-learning record showing what can be repeated, what stalls, and what must be addressed before expansion.

The adapted ME(R)L cycle is:

```text
Existing information
→ monitoring
→ DCCE-convened evaluation
→ targeted research where necessary
→ focused learning near the weak point
→ proposed change
→ next monitoring round
```

Third-party verification was correctly removed from the current project. CRDB-informed data practices remain useful as quiet supports—clear sources, indicator descriptions, simple checks, reusable files, and issue logging—without presenting data governance or system architecture as a new DCCE obligation.

## What failed

The generated deck was fragmented. It placed assumptions, risks, dependencies, roadmap changes, and deliverables beside one another without a strong causal bridge. The result read as a stitched checklist rather than an executive argument.

The main failure was upstream of design and code. The deck was not first reduced to a single decision thesis and a sequence of narrative movements. Visual structure then amplified the fragmentation: every analytical category received a slide, tables carried too much explanatory burden, and transitions did not tell Boss why the next point followed from the previous one.

The deck's HTML and slide-count checks created false confidence. They verified that the file worked as a presentation object, not that the presentation persuaded, clarified, or respected the reader's cognitive path.

## Lessons

### Narrative precedes component coverage

For complex institutional analysis, a complete inventory of topics can still produce an incoherent deck. The deck needs one governing sentence, a defined decision request, and a causal chain. Components should appear only when they advance that chain.

### The executive decision must be explicit

The next deck should ask Boss to approve a sequencing proposition:

> The roadmap keeps its six capabilities and 2030 ambition, while the 2026 project tests one bounded operational cycle and makes dependencies and readiness gates explicit before expansion.

Every slide should make this proposition more credible.

### The fixed TOR is a narrative constraint, not only a procurement fact

The 240-day, ฿3 million TOR and mandatory six-sector activities determine the shape of the feasible story. The deck should explain how six-sector coverage and one-sector depth coexist, rather than presenting them as competing scopes.

### Technical quality checks are insufficient

Thai language linting, density checks, fixed-stage checks, and JavaScript validation are useful release gates. They cannot replace a human coherence review. Before implementation, the next draft needs a prose read-through in which each slide can be summarized as “because this, therefore that.”

## Next session direction

1. Start with a one-page executive narrative, not HTML.
2. Define the decision Boss should make at the end.
3. Organize the deck into five movements: roadmap value; institutional friction; dependency chain; adapted roadmap; next-project decision.
4. Use one central information-to-decision diagram and reuse it as the deck's visual grammar.
5. Convert tables into selective evidence only after the narrative works without them.
6. Rebuild the deck in the chosen visual system and test both structural validity and human coherence.
