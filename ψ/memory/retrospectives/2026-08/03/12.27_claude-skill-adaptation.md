## Honest Feedback

Three friction points, named plainly. First: I over-claimed twice on harness mechanics I hadn't verified — skill precedence being the clearest case, stated confidently and then falsified by the very next `/rrr` invocation. Second: the adaptation work had a hidden second layer (executable scripts behind the `SKILL.md` prose) that I didn't think to check until the user pointed at it twice — I was pattern-matching "SKILL.md edited" to "skill adapted" without checking what it calls out to, which is exactly the kind of surface-level completion the `Verify Before Reporting` rule in `recap`/`rrr` itself warns against, and I fell into it anyway while implementing that same skill. ## Lessons Learned

Harness-mechanics claims (skill resolution order, tool discovery paths) are empirical facts about this specific system, not things to reason about from first principles or prior assumption — they need a live test before being stated, every time, not just the first time it bites. Separately: when a `SKILL.md` says "run script X," adapting the skill means checking script X's actual content, not just the markdown that references it — the delegation boundary is exactly where stale agent-specific code hides.

[→ AGENT DECISION] I stated "Claude Code will discover them here, project-scoped, taking priority over the global `~/.claude/skills/` versions" as settled fact after copying skills into `.claude/skills/`, without running `/rrr` or any other invocation to confirm it. That was the wrong call — it should have been phrased as an assumption pending verification, and I should have proactively tested it right then rather than waiting for the user to invoke `/rrr` and discover the contradiction themselves.
