## AI Diary

This session had an unusually tight feedback loop between what I was analyzing and how I was behaving. Early on, I got corrected twice for the same underlying mistake — launching a subagent to re-derive research that already existed in a trace log, then proposing to re-derive a CRDB gap analysis that was already logged from a `/trace --deep` I myself had run two turns earlier. Both times the user's correction was some version of "check what already exists first." By the end of the session, that exact principle became the spine of the TOR70 critique itself: the TOR instructs a contractor to rebuild what CRDB already delivered. I don't think that's a coincidence I should read too much into structurally, but it did make me more careful, and I noticed myself deliberately checking for existing artifacts before each subsequent research step.

The writing-th harness portion was the most mechanically satisfying part of the session. Being told exactly what the lint gate caught — real contrast-scaffolding, a moralizing verb, an unnamed passive actor — was more useful than being told "make it sound more natural," because I could see precisely which sentence-level habit I'd imported from English. I also made a real mistake there: a blind find-and-replace to fix one lexicon violation corrupted a markdown link elsewhere in the file. The gate caught it before it went anywhere, which is exactly what a gate is for, but it's a reminder that global replace on natural-language content is never actually safe, even for a two-character acronym.

The honest-critique exchange over the user's independently-produced deck version felt like the highest-value moment of the session for reasons unrelated to the deck itself: I was asked to evaluate work that competed with my own prior draft, and I could name what was genuinely better (the institutional caveats, the operator table) without either over-crediting or under-crediting it relative to mine. That's a harder thing to do honestly than it sounds.

## Honest Feedback

Three friction points worth naming. First, I proactively spawned a research subagent early in the session before checking whether the answer already existed — a real process failure that cost the user a "kill the subagent" interruption, and it happened again in miniature when I proposed re-deriving CRDB gap material the user had to correct me on directly. The lesson landed, but it took two corrections to land, not one.

Second, my own English deck draft (11 slides) undersold the strongest number in the whole analysis — the 45%→62% coverage lift — by treating it as one bar chart slide among several, rather than making it the single number the deck exists to deliver. The user's independent revision made the opposite mistake in the other direction, burying that same number in an appendix. Neither of us landed on the right prominence for it on the first pass, which suggests the actual difficulty wasn't drafting the slide, it was judging how much weight one number should carry against institutional/procedural content competing for the same slide real estate.

Third, the blind find-and-replace during the Thai translation lint-fix pass was avoidable — I was fixing a single flagged lexicon term and used a global string replace without checking whether that string appeared elsewhere in a context where substitution would be wrong (a file path). The gate caught it, but a more careful fix (scoped to the specific flagged sentence) would have avoided needing the gate to catch it at all.

## Lessons Learned

- **Check for an existing trace or log before spawning research, even mid-analysis.** This applies not just at task start but every time a sub-question comes up — the second correction in this session happened because I treated a new sub-question as needing new research rather than checking whether a prior `/trace --deep` in the same session already answered it.
- **Verify a document's own existing claims before building on them, even when you didn't write them.** The "only one feedback loop" error was already sitting in the storyline file from an earlier session turn; the deviation-analysis task's verification pass caught it only because clause-level grep was run as a matter of course, not because the error was suspected in advance.
- **When two independent drafts exist, name what's better in each rather than picking a winner.** The comparative critique of the user's improved deck worked because it separated "real institutional improvement" from "structural regression" instead of an overall verdict — this is a more useful shape of feedback for a collaborator's own work.
- **A lint/gate pipeline is only as safe as the fixes fed into it, not just the gate itself.** Global find-replace inside natural-language Thai content should be scoped to the specific violation's context, never applied blindly across a whole file, even for a short flagged term.
