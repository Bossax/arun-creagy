## Honest Feedback

**Friction 1**: The style-capture skill's resolution ladder treats "working
copy diff is non-empty" as sufficient grounds to proceed as if it were a
human edit. In this project, at least three distinct non-edit shapes can
produce a non-empty diff on a report-section file: an outline renumbering
that moves unrelated content under the same filename, a pipeline
regeneration re-verbalizing the same argument map, and an actual human edit.
The skill's own doc only accounts for the last one. I compensated by asking
each time, but that's a workaround, not a fix — a lighter-weight check
(e.g., "does this file's last commit look like a fresh AI-generated draft
with no intervening edit, per commit message conventions?") could catch the
outline-reshuffle case automatically before I burn a round-trip asking.

**Friction 2**: `check_term_propagation.py` surfaces stale usages of
superseded terms across the whole project, including files that are
explicitly archived/broken (`_archive-wrong-section-mapping/`, `_broken/`).
I had to eyeball each hit to judge whether it was live report content worth
flagging to the user or dead-end scaffolding not worth mentioning. A
`--exclude` convention for underscore-prefixed "not real" directories would
cut noise from that report without losing real hits.

**Friction 3**: The rationale-gate `AskUserQuestion` calls worked well, but
in the §4.5 round the user's free-text answer to the timeline-figures
question didn't map cleanly onto any of the three preset options — it named
a *different* underlying rule (a writing-plan scope boundary) than any option
anticipated (style preference / content correction / not deliberate). That
turned out fine because the answer was still unambiguous, but the options I
wrote assumed the space of likely answers too narrowly. Worth remembering:
frame these more open-ended when the diff category is itself uncertain,
rather than trying to pre-guess the answer shape.

## Lessons Learned

- A non-empty working-copy diff on a report-section file is necessary but
  not sufficient evidence of a human style edit — outline reshuffles
  (content moved to a differently-numbered section, same filename reused)
  and pipeline re-verbalization runs both produce real diffs that read as
  edits but carry zero style signal. Confirm provenance with the user before
  running the zero-drop audit whenever the diff's *shape* is a wholesale
  content rewrite (new paragraphs, added facts/figures, restructured lists)
  rather than word/sentence-level correction.
- Rationale-gate answers can reveal a rule bigger than the candidate being
  asked about. The §4.5 timeline-figure drop was framed as "is this a style
  preference," but the real answer was a writing-plan scope boundary (don't
  presume unresolved next-TOR details) that belongs in `writing-th`'s
  contract-validation logic, not the style pack. When an answer names a rule
  outside style-capture's remit, surface it as a distinct follow-up rather
  than force-fitting it into `content_correction` and moving on.
