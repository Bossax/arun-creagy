## Lessons Learned

- **Two-taxonomy plan documents are a real trap.** A single writing-plan file covering both a Full Report and an Executive Summary, with independently-numbered Chapter 4 sections in each, will silently misdirect drafting if Stage 0 doesn't explicitly confirm which taxonomy's section a contract is being built against. This should be a standing Stage 0 checklist item for this project going forward, not something re-discovered each time.
- **A citation naming a specific number (like "47 of 75") is a claim that must be checked against its named source before being reused, not assumed correct because it appears in an existing artifact.** An unverified figure surviving in an archived argument map is exactly as dangerous as one freshly invented.
- **When a skill names a specific tool for a specific purpose (`oracle_search`/`oracle_trace` for retrieving a plan's relevant slice), use that tool as specified before reaching for a broader, less-targeted alternative** — especially when the broader tool (a cross-session learnings search) has an obviously different purpose than what's needed (this project's own evidence documents).
- **When an argument unit claims full coverage of an enumerable set (e.g., "each of the 9 services"), verify the grounds actually cover all of it before accepting a partial illustrative version as sufficient** — the fix here was one grep away in the actual source report.
