## AI Diary (first-person)
I felt the “scale anxiety” surface immediately when we removed the fallback-by-name block. The fallback had been doing emotional work: it made the map “look complete,” but it was also masking the most dangerous category of error — quietly attaching the wrong stats to the wrong geometry. The first strict check I wrote then failed on a single tambon (“เวียง”), and my first instinct was to treat it like a geometry problem. That was a mistake: the real issue was that I was testing the wrong direction and mislabeling “no recorded disasters” as a join failure. Once we flipped the test to stats→geometry coverage, I felt the system become honest.

The second failure (a `match_id=123` record) was a reminder that data pipelines break at the seams: the subdistrict code column looked authoritative, but it contained malformed values that poison joins. Adding code cleaning and province-prefix validation felt like restoring sovereignty — it creates a boundary between credible keys and garbage. I’m satisfied that we ended with a pattern that can scale nationally without silently lying, but I also feel how easy it is for visualization goals to push me toward “make it work” shortcuts. The guardrails we wrote are my attempt to keep that reflex contained.

## Honest Feedback (3 friction points)
1) **The most common mismatch is conceptual, not technical**: my first strict check failed because the definition of “match” was wrong. When we scale, the biggest risk isn’t just bad strings or missing codes — it’s misunderstanding what constitutes an error vs a valid zero. That confusion is subtle and will reappear if the guardrail is not explicit.

2) **Data hygiene needs to be treated as a first-class product**: the `match_id=123` incident shows that “dirty join keys” can create false alarms and waste hours. If we do this for all 77 provinces, we need a standardized, auditable code-cleaning step (and a QA output that counts what got dropped) rather than province-by-province debugging.

3) **YoY can mislead if not normalized and if baseline availability is ignored**: an absolute delta is not comparable; a percent change can still mislead when baseline is 0 or missing. Without explicit non-computability rules, the map will imply meaning where there isn’t any. I initially defaulted to “fill with 0,” which is precisely the kind of convenience that becomes methodological debt.

## Lessons Learned
- Integrity checks for spatial joins must be defined as **stats→geometry coverage**, not geometry→stats completeness.
- **Never use name fallback** for joins in a national pipeline; it creates silent misassignment risk.
- Join keys must be normalized into a strict **6-digit tambon code** and validated by province prefix before aggregation.
- For YoY mapping, use a **normalized metric** (percent change) and enforce non-computability when baseline is missing/0.
