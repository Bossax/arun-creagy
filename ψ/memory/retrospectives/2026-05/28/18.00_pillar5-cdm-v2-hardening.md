## Architecture Decisions
- **Normalization to Domains**: Transitioned from vague "Subject Areas" to strict "Domains" with subdivision owners.
- **Determinant Neutrality**: Forced both Vulnerability and Resilience frameworks to reference the same VULNERABILITY_DETERMINANT table, preventing data duplication.
- **Polymorphism**: Used VULNERABILITY_DEFINITION as a logical gateway to separate Math-based impact functions from Index-based policy frameworks.

## Lessons Learned
- **The "Neutral Fact" Pattern**: In climate resilience, data is often reused across competing frameworks. Storing data as neutral "determinants" and mapping them via "structures" is the only way to avoid 10x data growth.
- **Traceability as a Seal**: A technical specification is only as good as its traceability. Aligning every entity with a Term ID from the glossary makes the model legally and scientifically defensible.
