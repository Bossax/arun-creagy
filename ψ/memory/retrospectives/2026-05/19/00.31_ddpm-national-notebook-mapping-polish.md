## Honest Feedback (100+ words, 3 friction points)
1) Notebook editing via JSON patches is inherently brittle — small quoting differences or formatting changes can cause patch misses or invalid JSON. It slows iteration compared to editing a `.py` file. 2) The Windows encoding issue around `ψ` is a recurring friction point; it caused `jupyter kernelspec list` to fail via cp1252 stdout. This is predictable and should be handled as a standard runbook step (force UTF-8 output). 3) Map rendering at national tambon resolution is heavy; while GeoPandas+Matplotlib works, it can be slow depending on environment. We mitigated interpretability with province overlays and colorbar sizing, but performance might still require future optimization (tiling / caching) if the notebook becomes part of routine workflows.

## Lessons Learned
- Visual improvements should be implemented in shared plotting utilities (`plot_national_metric()`) and global `mpl.rcParams`, not scattered per-cell edits.
- Always treat percentiles as part of the data contract: if the intent is “national percentiles”, the notebook should read `pct_national_*` from Gold and avoid recomputing ranks on filtered subsets.
- Windows terminals + cp1252 are incompatible with ψ/Thai paths unless UTF-8 output is enforced.
