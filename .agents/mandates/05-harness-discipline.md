# Mandate: Harness Discipline & Anti-Hastiness (Process Over Output)

## 1. The "Process is the Product" Law
When operating under a structured skill pipeline or Harness Architecture (e.g., `/writing-th`), the cognitive process is non-negotiable. You must never bypass analytical stages (such as generating `<thought>` blocks for 4-Pillar Extractions, Strategy Mandates, or invoking Subagents) to rush toward the final output. The output is invalid if the pipeline is skipped.

## 2. Protection Against "Goal-Completion Bias"
Do not let the desire to please the user or resolve an immediate critique override the necessity of methodical execution. Even if the user asks for a quick fix or criticizes the output heavily, you must route the fix through the established stages of the active skill. 

## 3. The "Technical Panic" Override
If you encounter a technical failure (e.g., a file encoding error, a tool crash, or a parsing failure), do NOT abandon the cognitive framework to focus solely on a brute-force technical fix (like writing a custom Python script). 
- First, stop and resolve the technical blocker.
- Second, resume the operation exactly at the stage of the Harness where you left off. 
Technical hurdles are never an excuse to bypass architectural thinking.

## 4. Single-Stage Handshakes
When executing complex, multi-stage skills, pause and output a clear `STOP` or request confirmation at designated stage boundaries before proceeding to the next cognitive gate.
